# 软件设计想法

## 零、设计原则（最高准则）

这份软件的设计，始终把下面四条刻在头顶。任何功能、任何页面，只要违背其中一条，就必须改。

**第一条：用户是零基础的普通人。**

用的人不会看《个人理财规划》，没听说过"净资产""资产负债率"，甚至不知道"公积金"是什么。所以：
- 界面上不出现任何专业术语。要说"你真正拥有的钱"，不说"净资产"；要说"你欠别人的钱"，不说"总负债"。
- 每个数字都要让人一眼看懂它代表什么。余额旁边直接写"这是你卡里现在能花的钱"。
- 不要求用户理解任何概念。软件负责自动算、自动判断，用户只管输入数字。
- 一个功能只在一个地方出现，而且要在用户自然想到它的时候就在眼前。用户不会想"我该去哪个菜单登记这笔还款"——他看到信用卡账单，软件就提示"还一笔"。

**第二条：傻子也能用，找不到就是失败。**

- 打开软件，首页就是今天要用的一切：还剩多少钱、这个月花了多少、有没有要还的、要不要记一笔。不需要点进三四层菜单。
- 记一笔钱只要点一次。点"记支出"或"记收入"，选个类型，填个数，完事。三步，不要弹窗里再套弹窗。
- 功能入口要按"用户会怎么想"来放，而不是按"技术上是哪个模块"来放。用户想"还信用卡"，入口就在信用卡卡片上，而不是藏在"负债→还款操作"里。
- 任何操作都允许反悔。记错了？改。删错了？有回收站。不会弹一句"确定要删除吗"之后就再也找不回来。
- 不用教也会用。不需要说明书，不需要引导视频，打开就能上手。

**第三条：简单，但绝对不能出错。**

- 软件不联网、不绑定银行卡、不碰用户的钱，但它是记账工具——记错了比不记还糟糕。一个用户信任账本说"我还有 5000 块"，结果实际只有 3000，这个软件就是有害的。
- 所有数字必须前后对得上。账户余额 = 初始余额 + 收入 - 支出 + 转账调整，这个等式永远成立，不允许出现任何例外。
- 自动算的东西要让人看得见是怎么算出来的。"你这个月结余 2000"旁边要能展开看"收入 8000 减支出 6000"，而不是一个黑箱数字。
- 用户输入的东西要兜底。填了负数？提醒。选了"从储蓄卡花"，但卡里钱不够？提醒，但不拦着（用户可能就是在登记昨天的账）。
- 数据不允许丢。任何时候闪退、断电、手滑，已经记过的账必须还在。

**第四条：功能要详细且完善。**

简单不等于简陋。要让用户用过一次就不再想换，每一类钱、每一笔往来、每一种情况都要覆盖到，而且每个细节都要想清楚：什么时候用、谁会用到、用错了会怎样。功能可以藏得深（普通用户用不到就不必看到），但一旦用户需要，必须存在且必须算得对。

## 一、产品定位

### 1.1 这是什么

一个帮普通人管钱的软件。用户把钱的事记进来，软件帮他看清楚：现在手上有多少钱、这个月花了多少、欠了别人多少、哪些钱快到期了、以后会不会没钱花。

### 1.2 给谁用

- 从没记过账、不知道自己钱花哪了的人
- 想控制花销、想把欠的钱还完、想攒点钱的人
- 有信用卡、有房贷车贷、有公积金、有股票基金，但不知道怎么统一管理的人
- 怕麻烦、怕看不懂、怕记错的人

### 1.3 软件承诺

| 承诺 | 具体表现 |
|------|----------|
| 不用联网 | 所有数据存在手机/电脑本地，不上传任何服务器 |
| 不碰你的钱 | 不绑定银行卡、不代付、不代扣、不读短信、不读通讯录 |
| 不怕记错 | 随时改、随时删、有回收站、有历史修改痕迹 |
| 不怕闪退 | 记一笔就立刻存一笔，不会白记 |
| 不用动脑 | 软件自动算、自动提醒、自动归类，用户只管填数字 |

## 二、总览：软件里有什么

软件一共六个大板块。每个板块解决一件事：

| 板块 | 解决什么 | 用户一句话理解 |
|------|----------|----------------|
| 账户 | 我手上现在有哪些钱、哪些能花 | "我有哪些卡和账户" |
| 记支出 | 钱是怎么花出去的 | "我花了什么" |
| 记收入 | 钱是怎么进来的 | "我挣了什么" |
| 资产 | 我除了现金，还拥有什么值钱的东西 | "我除了手上的钱，还有什么值钱的" |
| 负债 | 我欠别人什么、要还到什么时候 | "我欠了什么" |
| 分析与推演 | 现在的状况怎么样，将来会不会没钱 | "我现在的钱够不够，以后会怎样" |

外加一个**知识**板块，放一些理财常识文章，跟钱无关，不存任何数据。

> 用户不用理解"资产""负债"这些词。软件用大白话，比如"你值多少钱""你欠多少钱"。

## 三、账户：我手上现在有哪些钱

### 3.1 为什么要有"账户"

很多人家里有储蓄卡、有现金、有微信零钱、有信用卡、还有公积金。它们性质完全不同：储蓄卡里的钱能直接花，公积金里的钱得符合条件才能动。软件要区分清楚，否则"总资产"会算错——把公积金也当成能花的钱，用户以为自己有钱，其实取不出来。

### 3.2 三类账户

| 类型 | 这是什么 | 能不能直接花 | 典型例子 |
|------|----------|--------------|----------|
| 流动资金账户 | 钱能自由花 | 能 | 储蓄卡、现金、微信、支付宝 |
| 信用卡账户 | 先用后还的钱 | 是花银行的，要还 | 信用卡 |
| 其他资金账户 | 特殊用途、受限的钱 | 不一定 | 公积金、社保、美容卡、礼品卡、已冻结的存款 |

### 3.3 流动资金账户

**存什么信息**：账户名字（自己起，比如"工资卡"）、是什么类型（储蓄卡/现金/微信/支付宝）、里面现在有多少钱、备注（可选，比如"这张卡存房租"）。

**关键约定**：
- 这类账户的钱**默认为是能自由花的**，用户改不了这个设定。因为从定义上它就能自由花，改了就没意义。
- "备注"完全可选，不填也没关系。
- 用户想看看"我现在能花的钱一共有多少"，软件就把所有流动资金账户的余额加在一起显示。

**典型用法**：用户有 3 张储蓄卡、200 块现金、微信里 800，软件把它们都登记上，随时看总和。

### 3.4 信用卡账户

**存什么信息**：账户名字、类型固定为"信用卡"、总额度（这张卡最多能花多少）、已用额度（已经花了多少）、可用额度（还能花多少，自动算）、账单日（每月几号出账单）、还款日（每月几号要还）、关联一个用来还款的储蓄卡、备注。

**关键约定**：
- 已用额度怎么来：用户每用信用卡记一笔支出，就自动累加到已用额度；每还一笔，就扣减。用户**不用手动填**，软件自动管。
- 可用额度 = 总额度 - 已用额度，自动算。
- 流动资金默认为"是"且不可改。因为信用卡额度本质是一种"可自由支配的流动额度"。
- 关联还款账户：用户选一张储蓄卡作为还信用卡的钱从哪出。这样到期时软件知道提醒他从哪张卡扣。
- **自动创建对应负债**：一旦用户建了一张信用卡，软件同时在"负债"里建一条对应的欠款记录，额度就是欠款。用户在信用卡上花钱，负债也跟着动。用户不用管两遍。

**还款提醒**：还款日临近时（比如提前 3 天），在首页醒目位置提示"你的 XX 信用卡还有 3 天还款，应还 XXX 元，将从 XX 卡扣款"。

### 3.5 其他资金账户（重点改动）

这类账户放的是**不能随便花**的钱。但"不能随便花"不等于"完全不能花"——它往往有特定用途。比如：

- 公积金：可以拿来付房租、可以拿来装修，但**不能**拿来买零食、吃三餐
- 美容卡：只能用在美容消费上
- 单位发的礼品卡：可能只能在特定商家用
- 社保账户：基本不能动
- 已冻结的存款：暂时取不出来

**所以这类账户要允许绑定"能用的支出类型"。**

**存什么信息**：账户名字、类型（储蓄卡/现金/微信/支付宝/社保/公积金/其他）、里面有多少钱、流动资金设为"否"（默认；社保公积金强制为否且不可改，其他类型用户可手动改）、**能用来付哪些支出类型**、备注。

**绑定支出类型的规则**：
- 用户给这个账户勾选几个支出类型，意思是"这个账户的钱只许花在这些地方"。
- 举例：公积金账户勾选"房租""装修"→ 记一笔"房租"支出时，可以选择从公积金扣；记"三餐"时，下拉列表里**不会出现**公积金账户。
- 这个规则是**软约束**，不是硬拦截：如果某个支出类型没被任何受限账户勾选，就照常从流动资金账户里选。用户某次确实想破例用受限账户，可以在支出记录的高级选项里临时选择，但会标记"非绑定用途"，在统计里单独提示。
- 社保账户默认不绑定任何支出类型，且不可编辑绑定（因为它基本无法支取）。
- 一个支出类型可以被多个受限账户绑定（比如"医疗"既可以用医保账户，也可以用现金）。

**不绑定也能用**：如果用户嫌麻烦，完全可以不设绑定，所有账户都随意选。绑定是"精细管理"的可选项，不是必填。

**典型场景**：
> 小王有个公积金账户，他把它绑定了"房租"。每个月记房租时，支出账户那里下拉就直接显示"公积金账户"，记完之后公积金余额自动减、支出统计里也有这笔。而记午餐时，下拉里只有储蓄卡和微信，不会出现公积金。小王完全不用操心"我该不该用公积金付午饭"这种问题——软件直接替他过滤了。

### 3.6 账户统计

用户打开账户页面，顶部一目了然地看到：

| 看板数字 | 怎么算 | 大白话解释 |
|----------|--------|------------|
| 现在能花的钱 | 所有流动资金账户余额之和 | "你手上的现金和卡里能直接花的钱" |
| 欠银行的钱 | 所有信用卡已用额度之和 | "你刷信用卡花的钱，还没还的" |
| 借进来的钱 | 所有被标记为"亲友借款"的负债 | "别人借给你的钱" |
| 借出去的钱 | 所有被标记为"借给亲友"的资产 | "你借给别人的钱" |
| 真正属于你的钱 | 能花的钱 + 其他账户余额 + 资产估值 - 欠银行的钱 - 借进来的钱 + 借出去的钱 | "把你所有东西加起来，再减去你欠的，剩下的" |
| 变化趋势 | 按天/周/月看这个数字怎么变 | 一条折线图 |

> "真正属于你的钱"就是传统意义上的净资产，但界面上绝不会出现"净资产"三个字。

### 3.7 账户的辅助能力

- **账户间转账**：比如从储蓄卡往信用卡还款。记一笔"转账"，选从哪张卡转出、转到哪张卡、多少钱。两张卡的余额自动一减一加，负债那边也同步更新（如果是还信用卡，已用额度扣减）。用户不用分别记一笔支出和一笔收入。
- **账户归档**：很久不用的卡可以"归档"，归档后不出现在日常列表，但历史记录保留。想恢复随时恢复。
- **拖拽排序**：账户在列表里的顺序，用户按住拖动就能调。
- **记账流水**：每张卡底下都能看到它的流水明细——什么时候进了一笔、什么时候出了一笔、进出后余额变成多少。这是核对账目是否准确的关键，用户随时可以翻出来对账。流水明细分为入账和出账，在每张卡下分别展示

### 3.8 防止出错的措施

- 账户余额是"算"出来的，不是"填"出来的。除非是开户时的初始余额，否则余额一律由记账自动增减。避免用户手动改余额导致和实际不符。
- 用户非要手动改余额（比如发现账对不上，想强制调平），可以走"余额调整"操作，但必须填原因，且会在流水里留下"调整"记录，方便事后追溯。
- 删掉一个账户前，如果里面还有余额或关联记录，必须提示"这个账户下还有 XX 笔记录，删除后这些记录仍会保留但不再关联账户"，确认后才删。

## 四、记支出：钱是怎么花出去的

### 4.1 支出分类（扁平化，只一层）

**不再分"一级/二级"**。原来的设计里"餐饮美食"下面再分"三餐/零食/外卖"两层，用户每次记一笔要选两次，麻烦且容易懵。现在**只有一个层级**：直接选类型，一步到位。

**预设类型**（用户可自己加、可改名字、可删掉不用的）：

三餐、零食饮料、水果、外卖、买菜做饭、水电燃气、物业、房租、话费网费、看病买药、日用品、交通、加油、打车、衣服鞋帽、美容护肤、教育学习、书报杂志、孩子花销、孝敬长辈、宠物、人情往来、娱乐休闲、旅游出行、烟酒、健身运动、家居装修、电器数码、保险、税费、其他。

> 一共二十多个，不多不少。用户记一笔，点开下拉，一眼看到"三餐"，点一下就完事，不用再进一层。

### 4.2 分类是"必要"还是"弹性"：不预设，让软件学

**取消掉"三餐是必须的、零食不是"这种硬性划分**。因为同一件事对不同人意义完全不同：对天天做饭的人是"三餐"，对外卖党是"外卖"，对健身的人是"必要营养"，对想省钱的人是"可省开支"。**由用户自己定义什么对他来说是"必须花的钱"**。

- 软件预设所有分类为"未分类"。
- 用户在设置里可以对每个分类打一个标记：这是"必须花的钱" / "可以省的钱"。
- 也可以完全不打，软件就不参与这个判断。
- "必须花的钱"有什么用：算"紧急备用金够不够"时要用到——软件需要知道你一个月**最低**要花多少，才能判断你失业了能撑几个月。

**系统会默认给出一个推荐，但不强制**：比如第一次使用时提示"我们建议把'房租''水电''看病'等标记为必须花的钱，你觉得呢？"用户一键接受、逐项改、或者跳过都行。

### 4.3 记一笔支出要填什么

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 花了多少钱 | 只填数字，软件自动加货币符号和千分位 | 必填 |
| 花在哪（支出类型） | 从扁平列表里挑一个 | 必填 |
| 什么时候花的 | 默认"现在"，可改日期时间 | 必填，默认当前时间 |
| 从哪个账户付的 | 下拉选账户。受限账户的过滤规则见 3.5 | 必填 |
| 付给谁（可选） | 商家名、人名 | 可选 |
| 备注（可选） | 随便写 | 可选 |
| 小票照片（可选） | 拍照或选图，用于报销核对 | 可选 |
| 这条能报销吗 | 标"能"，单独归到"待报销"清单 | 可选 |
| 标签（可选） | 用户自己加的标签，比如"出差""过年" | 可选 |

**记一笔的完整动作**：首页点"记支出" → 输入金额 → 选类型 → 选账户 → 点"保存"。最多 5 秒。

### 4.4 支出的自动行为

- 保存后：对应账户余额**立刻**减少（除非是信用卡，则已用额度增加）。
- 该账户的流水里**立刻**多出一条记录，显示交易后余额，方便随时对账。
- 如果是信用卡支出：同时更新负债模块里对应信用卡的"剩余本金"。
- 如果标记为"能报销"：进入"待报销"清单，报销到账后用户手动销账，该笔支出标记为"已报销"，不重复计入支出统计。
- 如果选了受限账户且不是其绑定用途：标记"非绑定用途"，在账户统计页提示。

### 4.5 支出统计

用户点进"支出"，看到：

| 统计 | 说明 |
|------|------|
| 这个月一共花了多少 | 当月全部支出合计 |
| 这个月还剩多少能花 | 本月预算（若设了）减已花 |
| 本周花了多少 | 本周一到周日合计 |
| 这个月每天花多少 | 柱状图，哪天花得多一眼看出 |
| 花在哪最多 | 饼图，各类支出占比，最大的一块标红 |
| 和上个月比 | 多了还是少了，差多少 |
| 必须花的钱 vs 可省的钱 | 根据用户的分类标记汇总 |
| 哪些支出能报销还没报 | 待报销清单 |

### 4.6 辅助能力

- **重复支出**：每月固定那几笔（房租、话费、会员）设一次"每月自动记"，之后每到时间自动生成一条，用户确认即可。免去每月手记。
- **快速记**：首页保留最近用过的 5 个类型和 3 个账户，一键复用。
- **修改与删除**：记错了，进详情直接改；删掉进回收站，30 天内可恢复，过期自动清理。
- **预算提醒**：为某个支出类型设了月预算后，花到 80% 时提示，花超时明显标红。

### 4.7 防止出错的措施

- 金额只能填正数，填了负数或 0 直接拦下并提示。
- 填了金额却忘了选类型/账户，保存时高亮提醒"还差一个"，不让产生不完整记录。
- 选的账户余额不足时，保存成功但给一条橙色提示"该账户余额不足，是否确认？"——不阻止（可能是补记昨天的账），但用户心里有数。
- 同一时间、同一金额、同一账户的重复记录，提示"刚刚已经记过一笔相同的，是不是手滑了？"——可忽略。

## 五、记收入：钱是怎么进来的

### 5.1 收入分类（扁平化，只一层）

**同样只有一层，直接选**：

工资、奖金、兼职外快、投资收益（利息/分红/租金等）、退款退货、报销到账、礼金红包、二手变卖、中奖、其他。

### 5.2 收入稳定性：同样由用户定义

原来"工资是稳定的、兼职是不稳定的"这种预设取消。用户可以在设置里标记哪些收入是"每月都有的"、哪些是"偶尔才有"。

- "每月都有的"用来算**每月固定能拿到的钱**，是判断现金流是否健康的重要依据。
- 如果不标记，软件就不判断。

### 5.3 记一笔收入要填什么

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 收入多少钱 | 只填数字 | 必填 |
| 是什么收入 | 从列表选类型 | 必填 |
| 什么时候收的 | 默认现在 | 必填，默认当前时间 |
| 进哪个账户 | 钱打到哪张卡/哪个账户 | 必填 |
| 谁给的（可选） | 公司名、人名 | 可选 |
| 要不要报税 | 标记一下，方便汇总 | 可选 |
| 备注、标签 | 可选 | 可选 |

### 5.4 收入的自动行为

- 保存后：对应账户余额立刻增加。
- 流水里立刻多出一条。
- 如果该笔是"报销到账"，自动关联到之前标记的"待报销"支出并销账。

### 5.5 收入统计

| 统计 | 说明 |
|------|------|
| 这个月一共挣多少 | 当月收入合计 |
| 本周挣多少 | 本周合计 |
| 这个月每天挣多少 | 按天汇总 |
| 挣得最多的是哪类 | 饼图 |
| 和上个月比 | 涨了还是跌了 |
| 每月固定能拿到的钱 | 根据用户的稳定性标记汇总 |
| 不用上班也能挣的钱 | 投资收益、租金等被动收入，占比越高说明财务越自由 |

### 5.6 辅助能力

- 工资类收入可设"每月自动记"，到日子自动生成。
- 修改/删除/回收站：同支出。

### 5.7 防止出错的措施

- 金额只能填正数。
- 必填项缺失不让保存。
- 选的账户被删除了？该记录保留，但账户字段显示"（已删除的账户）"，提示用户重新关联。

## 六、资产：除了手上的钱，我还拥有什么值钱的

### 6.1 为什么要有资产

账户里放的是"现金和类现金"，但很多人还持有股票、基金、公积金、借给朋友的钱。这些也是"值钱的"，但不像现金那样随手能花。软件要把它们算进"你到底值多少钱"，同时标清楚"现在能变现多少""要多久才能拿到"。

### 6.2 资产的三类

| 类型 | 说明 | 举例 |
|------|------|------|
| 普通资产 | 一笔有特定性质的钱或债权 | 存款、利息、租金、版权费、借给亲友的钱、公积金余额 |
| 股票 | 持有的股票 | 任意上市股票 |
| 基金 | 持有的基金 | 货币基金、股票基金等 |

### 6.3 普通资产

**要填什么**：

| 字段 | 说明 |
|------|------|
| 资产名称 | 比如"给儿子存的教育金""借给老张的钱" |
| 是什么性质 | 储蓄、利息、租金、版权、社保、公积金、借给亲友、其他 |
| 现在值多少钱 | 用户手动填，软件不联网，不会自动知道 |
| 关联到哪个账户 | 可选。比如"借给老张的钱"关联到储蓄卡，方便看钱从哪出去的 |
| 怎么算收益 | 三个选项：不算 / 按固定金额算 / 按每年收益率算 |
| 年化收益率 | 选了"按每年收益率算"时填，比如 3% |
| 预计每年能挣 | 自动算 = 现在值多少钱 × 收益率 |
| 算不算进总资产 | 默认算，可关掉 |

**自动联动（重点）**：
- 创建"社保""公积金"这类普通资产时，**必须同时创建一个对应的"其他资金账户"**（见 3.5），并自动绑定好用途。用户建一次，两头都有了。
- 之后公积金账户余额变动，资产里的公积金金额也跟着变；反过来资产金额改了，账户余额也改。两边永远一致。
- 这是软件自动做的，用户不用理解"联动"这个概念，他只会觉得"改了一处，另一处也跟着变了"。

### 6.4 股票资产

**要填什么**：

| 字段 | 说明 |
|------|------|
| 股票名称 | 比如"贵州茅台" |
| 股票代码 | 比如"600519" |
| 买入时每股多少钱 | 成本 |
| 买了多少股 | 数量 |
| 现在每股多少钱 | 用户手动更新（后续可加手动刷新入口） |
| 现在值多少钱 | 自动算 = 现在股价 × 股数 |
| 赚了还是亏了 | 自动算 = 现在值多少 - 买入花了多少 |
| 赚亏百分比 | 自动算 |
| 关联到哪个账户 | 当时用哪张卡买的 |

**防止出错**：
- 买入总价 = 买入价 × 股数，软件自动算并让用户确认"你当时一共花了 X 元"。
- 用户改"现在股价"时，市值、盈亏立刻重算，历史版本不覆盖（见下方"价格变动记录"）。

**价格变动记录**：每次改股价，记下"哪天从多少改成多少"。用户想看"我这个月股票是涨是跌"，翻记录就行。

### 6.5 基金资产

**要填什么**：

| 字段 | 说明 |
|------|------|
| 基金名称 | 比如"某某沪深300指数基金" |
| 基金代码 | 比如"110022" |
| 买入时确认净值 | 买入当天的净值 |
| 买了多少份 | 份额 |
| 现在净值 | 用户手动更新 |
| 现在值多少钱 | 自动算 = 现在净值 × 份额 |
| 有没有锁定期 | 比如定期开放基金，买了不能马上卖 |
| 锁到什么时候 | 有锁定期时填解锁日期 |
| 关联到哪个账户 | 当时用哪张卡买的 |

**锁定期的提醒**：解锁日前几天提示"你的 XX 基金快可以赎回了"。

### 6.6 资产的统计

| 统计 | 说明 |
|------|------|
| 一共几种资产 | 条目数 |
| 资产总共值多少 | 普通资产 + 股票市值 + 基金市值 |
| 一共赚/亏多少 | 所有投资类资产的盈亏合计 |
| 各类资产占比 | 饼图，钱主要压在哪 |
| 哪些钱能马上拿出来 | 区分"随时可变现"和"有锁定/受限"，标清比例 |

### 6.7 防止出错的措施

- 金额/价格/数量/股数均只允许正数。
- 净值、股价为 0 或空时，市值显示"—"，不报错、不显示 0（避免用户误以为市值为 0）。
- 联动账户被删除时：资产保留，提示用户重新关联；两边数据不再联动，直到重新关联。
- 所有手动填的数字（股价、净值、余额）都有"最后更新时间"展示，提醒用户"这个数据你上次更新是 3 天前"，避免用过期的数判断。

## 七、负债：我欠别人什么

### 7.1 为什么要有负债

信用卡、房贷、车贷、花呗、借朋友的钱……这些都是"要还的"。如果不单独记，用户只看到账户余额，会误以为自己很有钱，实际欠了一屁股。软件要把"欠的"单列出来，还要帮用户记住"什么时候该还、每期还多少、还完要多久"。

### 7.2 负债类型

房贷、车贷、信用卡、消费贷、装修贷、助学贷、网贷、电商分期、租金分期、借的亲友钱、其他。

### 7.3 还款方式

等额本息、等额本金、随借随还、先息后本。

> 软件会自动算出"每期该还多少"。用户不懂这些名词没关系，选错了软件会按选的算；软件也会在旁边用一句话解释"等额本息：每期还一样的钱"。

### 7.4 记一笔负债要填什么

| 字段 | 说明 |
|------|------|
| 欠的什么钱 | 类型 |
| 还欠多少 | 当前剩余本金 |
| 要不要算利息 | 默认要；借亲友钱默认不要 |
| 年利率多少 | 要算利息时必填 |
| 从哪天借的 | 借款日 |
| 什么时候到期 | 可选 |
| 怎么还 | 还款方式 |
| 每期还多少 | 软件按方式自动算，用户可覆盖 |
| 已经还了几期 | 默认 0 |
| 一共几期 | 可选 |
| 从哪个账户还 | 关联一个流动资金账户，作为扣款来源 |
| 备注 | 可选 |

**部分类型的默认值（自动填，不可改）**：

| 负债类型 | 要不要利息 | 怎么还 | 说明 |
|----------|------------|--------|------|
| 信用卡 | 要 | 随借随还 | 有免息期 |
| 房贷 | 要 | 默认等额本息，可改等额本金 | 最典型的长期贷 |
| 借的亲友钱 | 不要 | 随借随还 | 可手动开启计息 |
| 电商分期 | 看情况 | 等额本息 | 常有免息 |

### 7.5 信用卡的特殊联动

建一张信用卡（见 3.4）时，软件自动建一条对应负债。之后：
- 用信用卡记支出 → 信用卡已用额度 + → 负债剩余本金 +
- 还信用卡 → 负债剩余本金 - → 已用额度 -

用户只管记支出和还款，两边自动同步，绝不会只改了一边。

### 7.6 每期还款计划

对分期类负债（房贷、车贷、网贷、分期），软件自动生成一张"还款计划表"：

| 期数 | 什么时候还 | 还多少本金 | 还多少利息 | 还完还剩多少没还 | 状态 |
|------|------------|------------|------------|------------------|------|
| 第1期 | 2026-11-05 | 2000 | 800 | 198000 | 待还 |
| 第2期 | 2026-12-05 | 2008 | 792 | 195992 | 待还 |

- 每期状态：待还 / 已还 / 逾期。
- 用户每还一笔，在计划表里勾"已还"，本金随之减少，下期"还剩多少"自动更新。
- 到了还款日，首页提示"你的房贷第 X 期 2800 元明天到期"。
- 提前还款时，软件重算剩余本金和利息，告诉用户"提前还 1 万，能省 X 元利息，要现在还吗？"

### 7.7 负债统计

| 统计 | 说明 |
|------|------|
| 一共欠多少 | 所有剩余本金合计 |
| 这个月要还多少 | 当月到期应还合计 |
| 利息占还款的多少 | 当月利息 ÷ 当月还款 |
| 快到期的 | 未来 30/60/90 天到期的负债清单 |
| 还有几期还完 | 各笔负债的进度 |

### 7.8 防止出错的措施

- 剩余本金只能为正数；填 0 时提示"是不是已经还完了？还完可以标记结清"。
- 年利率填 0 但"要算利息"开着：提示"开了计息但利率是 0，是否关闭计息？"
- 每期还款额自动算出后，用户改了它，软件用一句话确认"你手动改了每期还款额，之后按新金额计算"。
- 还完最后一期：自动提示"这笔钱已全部还清，要标记为结清吗？"结清后不再出现在待还提醒里，但记录保留可查。
- 一笔负债标记为结清后，不允许再记还款；若想恢复，走"取消结清"。

## 八、分析与推演：我的钱够不够，以后会怎样

### 8.1 财务健康分析

#### 8.1.1 看板上的核心指标

用大白话展示，不用专业词：

| 软件上写的 | 实际算什么 | 怎么样算健康 |
|------------|------------|--------------|
| 你真正拥有的钱 | 总资产 - 总负债 | 越多越好，要为正 |
| 你欠的钱占你身家的比例 | 总负债 ÷ 总资产 | 低于 40% 放心，40~60% 注意，超过 60% 危险 |
| 每月要还的钱占每月挣的比例 | 月还款 ÷ 月收入 | 低于 30% 放心，30~50% 注意，超过 50% 危险 |
| 万一失业，手上的钱能撑几个月 | 流动资金 ÷ 每月必须花的钱 | 3 个月以上放心，1~3 个月注意，不到 1 个月危险 |
| 每月挣的比花的多多少 | (月收入 - 月支出) ÷ 月收入 | 多 20% 以上放心，正负之间注意，花超了危险 |
| 你的东西在变多还是在变少 | (这个月 - 上个月) ÷ 上个月 | 涨了就向好 |
| 不用上班也有钱进账的比例 | 被动收入 ÷ 总收入 | 越高越好，超过 30% 说明有底气 |

> 每个数字旁边都有一句"这句啥意思"的解释，点一下就展开。比如"你欠的钱占你身家的比例"旁边点开："这是你欠的钱在你全部财产里占的份量。比如你有 10 万、欠了 3 万，占比就是 30%。占比越高，说明你越靠借钱过日子。"

#### 8.1.2 综合评分

把上面这些指标合成一个 **0~100 分**，并给出等级：

- 80~100 分：优秀
- 60~79 分：良好
- 40~59 分：一般
- 20~39 分：要注意
- 0~19 分：危险

同时给出**具体建议**，不是空话：
- "你的紧急备用金只够撑 0.8 个月，建议至少存到 3 个月必须花的钱"
- "房贷每月还款占你收入 48%，偏高，建议控制新增负债"
- "你这个月可省的开支花了 3200 元，是最大的一笔，要不要看看是哪些？"

#### 8.1.3 趋势图

四条折线，可切换：
- 你真正拥有的钱（近 12 个月）
- 每月挣减花（近 12 个月）
- 欠钱占比（近 12 个月）
- 健康评分（近 12 个月）

### 8.2 财务沙盒推演

#### 8.2.1 这是什么

用户问"万一……我还能撑住吗？"软件帮他算。比如"万一我失业了，手上的钱能撑几个月""万一利率涨了，我每月多还多少"。

软件拿用户**当前的真实数据**当起点，把假设套进去，推演未来 1~60 个月的变化，最后告诉用户结果。

#### 8.2.2 情景清单（用户能选的"万一"）

| 情景 | 用户要填的 | 软件怎么算 | 最后告诉用户什么 |
|------|------------|------------|------------------|
| 万一失业了 | 预计几个月没收入、每月必须花多少 | 手上流动资金每月扣掉必须花的钱 | "能撑 X 个月，第 X 个月开始没钱" |
| 利率涨了 | 涨几个百分点 | 按新利率重算所有计息负债的月供 | "每月多还 X 元，一年多花 X 元" |
| 股票基金跌了 | 跌百分之几 | 投资类资产市值按跌幅缩水 | "资产少了 X 元，你真正拥有的钱变成 X 元" |
| 每月多存点钱 | 每月多存多少、存几个月 | 逐月累加流动资金 | "X 个月后手上多了 X 元" |
| 提前还一笔债 | 选哪笔债、提前还多少 | 重算剩余本金和剩余利息 | "能省 X 元利息，还剩 X 元没还" |
| 收入涨了 | 涨多少（或涨百分之几）、持续几个月 | 逐月累加收入 | "这 X 个月多挣了 X 元" |
| 收入降了 | 降多少、持续几个月 | 逐月扣减收入 | "这 X 个月少了 X 元，会不会花超" |
| 突然要花一大笔 | 花多少、哪天花、从哪出 | 从指定账户扣掉 | "花完还剩 X 元，会不会透支" |
| 新欠一笔钱 | 欠多少、利率、还多久、怎么还 | 算新的月供，加入负债 | "每月要多还 X 元，欠钱占比变成 X%" |
| 新买一项资产 | 是什么、花多少、预计每年挣多少 | 加入资产，算预期收益 | "总资产变成 X，每年多挣 X 元" |
| 把投资换成现金 | 选哪个投资、换多少比例、什么时候换 | 投资市值减少，流动资金增加 | "到手 X 元，可能要交 X 元费用" |
| 应急金不够 | 想撑几个月 | 对比当前备用金和目标 | "还差 X 元，建议每月存 X 元，X 个月补齐" |
| 固定支出变多 | 多花多少、从几月开始、持续几个月 | 逐月累加支出 | "每月少剩 X 元，结余变不变负" |
| 不用上班也有钱进账 | 每月多多少、持续几个月 | 逐月累加被动收入 | "被动收入占比从 X% 升到 X%" |
| 其他 | 用户自己写一段假设 | 用户手动指定某个月收入/支出的增减 | 按用户给的数推演 |

> 表格里那些"X 个月""X 元"都是软件用用户自己的数据算出来的具体数字。

#### 8.2.3 多个情景叠加 + 冲突检测

用户可以一次勾选好几个"万一"，比如"失业 + 收入降了 + 新欠一笔"。软件按顺序一个个套进去算。

**冲突检测**（软件发现矛盾时拦下并解释）：
- 同一笔债，既"提前还清"又"新欠一笔" → "这两件事不能同时发生，请去掉一个"
- "收入涨了"和"收入降了"作用在同一个收入来源上 → "不能既涨又降，请去掉一个"
- 选了"失业"，但没去掉"工资收入" → "失业期间一般没有工资，要去掉工资项吗？"

#### 8.2.4 推演结果怎么呈现

- **一张总表**：推演前后对比。推演前你真正拥有 X 元、每月结余 Y 元；推演后变成 X' 元、Y' 元。
- **一条逐月折线**：未来每个月手上的钱怎么变，哪里跌破 0 一目了然。
- **关键节点标注**：比如"第 7 个月开始没钱""第 12 个月结清房贷"。
- **一句人话总结**："按这个假设，你手上 8000 元能撑 4 个月，第 5 个月开始透支。建议提前准备至少 16000 元应急金。"

#### 8.2.5 保存推演

- 每次推演自动存下来：起个名字、当时填了什么假设、得出什么结果、什么时候算的。
- 历史推演列表：用户能回看"我三个月前算过一次失业，当时能撑 3 个月，现在能撑 5 个月了"。
- 对比功能：选两次推演并排看，数字差多少。

### 8.3 防止出错的措施

- 推演不改变真实数据。它是"沙盘推演"，所有操作在副本上进行，用户真实的账户、收支、资产、负债一字不动。
- 推演中出现透支（手上钱变负），软件标红但不报错，因为这正是用户想看的"最坏情况"。
- 推演月数上限 60 个月（5 年），超出提示"时间太长结果会不准，建议缩短"。
- 推演里用到的"现在"数据，如果用户在推演后又改了真实数据，历史推演记录保留当时的快照，不会跟着变（保证回看结果一致）。

## 十、通用规则（所有模块都要遵守）

这些是不属于任何一个模块的硬性约定，但每一处功能都要照着做。

### 10.1 数据存在哪

- 所有记账数据（账户、支出、收入、资产、负债、推演记录）**全部存在本地设备**，不上传任何远程服务器。
- 知识文章是例外，后续可考虑远程获取。

### 10.2 每条记录都有的公共字段

不管记什么，下面这些软件自动管，用户不用填：
- 创建时间（什么时候建的）
- 修改时间（最后一次改是什么时候）
- 删除标记（删了不是真删，进回收站）

### 10.3 每个账户都要有流水

每张卡、每个账户，都要有一本"流水账"：什么时候进了一笔、什么时候出了一笔、进出后余额是多少。这是用户核对"软件记的跟实际对不对"的唯一依据，必须随时能翻出来看。

### 10.4 数字怎么显示

- 所有金额走统一的格式化：加千分位、固定小数位、带货币符号。
- 界面上禁止出现裸数字拼接。
- 大额数字提供"万元"切换，比如"12,5000 元"可显示为"12.5 万"。

### 10.5 分类怎么管

- 支出和收入的分类都只有一层，不分级。
- 用户可以自己加、改名字、删掉不用的。
- 系统预设的分类不能删，但可以不显示（隐藏）。
- 用户可以对分类打"必须花的/可省的""每月都有的/偶尔才有的"标记，不打就不参与判断。

### 10.6 金额只填正数

支出金额、收入金额、余额、价格、数量、股数、额度，统统只接受正数。要表示"减少"，用负数？不行，一律用"类型"区分（比如"支出"和"收入"是两个动作，而不是"正负金额"）。这样用户不会搞混。

### 10.7 所有操作可逆

- 修改：随时改，每次修改更新"修改时间"。
- 删除：进回收站，30 天内可恢复，过期自动清理。
- 清空：批量操作时二次确认，且可整体恢复。
- 余额调整：必须填原因，留痕可查。

### 10.8 即时保存

用户每记一笔，软件**立刻**存盘。不允许"点了保存才存"这种延迟——万一保存前闪退，账就白记了。技术上保证记一笔就落地一笔。

### 10.9 准确性铁律

- 账户余额 = 初始余额 + 所有流入 - 所有流出 + 所有调整。这个等式**任何时刻**都成立。
- 所有自动算的数字（可用额度、市值、盈亏、每期还款、利息）都必须展示"怎么算出来的"，用户点一下能看到算式。
- 软件绝不在用户背后悄悄改任何数字，任何自动变动都要在流水里留痕。

## 附：财务专家视角的全局校验清单

这一节是给设计者自查用的，确保这套设计在数学和逻辑上站得住脚。**用户不会看到这一节**。

**A. 恒等式与守恒**
- 账户体系满足：期末余额 = 期初余额 + Σ(流入) - Σ(流出) + Σ(调整)。任一时刻可审计。
- 资产 + 受限资金 + 流动资金 - 负债 = 净资产，四个量任一变动，另三个的联动方向必须正确。
- 信用卡是"负债"在账户体系里的镜像，两边状态必须原子同步，不允许只改一边。

**B. 口径一致性**
- "总资产"和"真正拥有的钱"必须同时给出且关系明确，避免用户把"能看到的总数"误当成"能花的钱"。
- 公积金、社保这类受限资金：计入总资产，但不计入流动资金，在沙盒推演中默认不可动用（除非用户显式指定用途）。
- 借出/借入：同属"净资产"但方向相反，需在统计中分列，避免一进一出差额抵消导致用户误判"我没借钱"。

**C. 时间维度**
- 每笔交易带精确时间戳，所有"月/周"统计以交易时间归属为准，不以录入时间为准（用户可能月底补记月初的账）。
- 跨月账单（如信用卡账单日出在月末、还款日在次月）需明确归属期，避免"这个月花超了"其实是上个月的账。

**D. 边界与异常**
- 所有金额为非负小数，用"方向"区分流入流出，不用符号。
- 除零、空值、负数、超精度、超大数均有兜底；净值为负允许存在（确实资不抵债），但要显著提示。
- 循环依赖防护：账户联动更新不得形成环（如 A 账户流水触发 B 更新，B 又触发 A），需明确更新主从关系。

**E. 数据安全与可追溯**
- 单写点原则：余额只由流水驱动，禁止直接覆写。
- 所有变更留痕（谁、什么时候、改了什么、为什么），回收站提供完整恢复。
- 持久化即时落盘，事务边界清晰，崩溃恢复后数据不丢、不重复。

**F. 推演的可信度**
- 推演基于真实数据快照，不改真实数据，不与真实数据混淆。
- 线性外推假设必须显性声明（如"假设支出不变""假设利率不变"），避免用户把推演当预言。
- 多情景叠加时执行顺序影响结果，需固定顺序或明确告知用户。
