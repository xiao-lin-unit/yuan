### 什么样的软件

做一个个人的财务管理软件

### 为什么要做

普通民众没有专业的财务知识，不会管理自己的资产，不会控制自己的债务，不能预测自己的财务风险，不堪其扰，所以要做一个面向所有大众的财务管理软件，帮助民众管理自己的财务，减少民众的困苦

### 应该有哪些功能

1. 账户

   - 账户分类：流动资金账户，信用卡账户，其他资金账户

     - 流动资金账户即字面意思，其中资金可自由流动的账户，大多是储蓄卡类型账户

       流动资金账户内容：账户名称，账户类型（储蓄卡，现金，微信，支付包），余额，流动资金默认为是，备注

     - 信用卡账户即字面意思，信用卡类型的账户，提前消费，然后还款

       信用卡账户内容：账户名称，账户类型（信用卡），总额度，已用额度，流动资金默认为是（不可修改），备注

     - 其他资金账户，大多表示不可自由流动的资金账户或者是用作特殊用途的资金账户，也可以是一个普通储蓄卡，但是流动资金选择否，如医保，公积金，美容卡等

       其他资金账户内容：账户名称，账户类型（储蓄卡，现金，微信，支付包，社保，公积金，社保和公积金默认流动资金为否，不可修改，其他账户类型如果要作为其他资金账户，则必须将流动资金选择为否），余额，备注

   - 账户统计：统计总资产，总负债，总借入，总借出，净资产，资产趋势，

2. 支出

   - 支出分类：三餐，水电，话费网费，日用品，住房，医疗，衣服，交通，汽车，孩子，零食，旅行，烟酒，学习，电器数码，运动，美妆，宠物，发红包，请客送礼，娱乐，其他，等等可自定义类型
   - 支出记录内容：支出分类，支出时间，支出金额，支出账户
   - 支出统计：月支出，本周支出，月每日支出，月分类支出

3. 收入

   - 收入分类：工资，奖金，兼职，副业，礼金，其他，等等可自定义类型
   - 收入记录内容：收入分类，收入时间，收入金额，收入账户
   - 收入统计：月收入，本周收入，月每日收入，月分类收入

4. 资产

   - 资产分类：
     - 普通资产
       - 细分类型：储蓄，利息，租金，版权，社保，公积金，亲友借款等等可自定义类型
       - 计算类型：无，按金额计算，按年收益计算
       - 内容：资产名称，资产细分类型，金额，关联账户，计算类型
     - 股票
       - 内容：股票名称，股票代码，买入价格，买入数量，创建时间，关联账户
     - 基金
       - 内容：基金名称，基金代码，确认净值，交易份额，是否有锁定期，锁定期限，创建时间，关联账户
   - 其他：在创建非信用卡账户时，要为该账户创建对应类型的普通资产，比如创建一个公积金账户时，要创建一个公积金资产
   - 统计：资产数量，资产金额

5. 负债

   - 负债类型：房贷，车贷，信用卡，消费贷，装修贷，助学贷，网贷，电商分期，租金分期，金鹰带，亲友借款，其他负债
   - 还款方式：等额本息，等额本金，随借随还
   - 内容：负债名称，负债类型，剩余本金，是否计息，年化利率，借款日期，还款方式，绑定账户，备注；部分负债类型的内容有默认不可修改值，需自动设置
   - 其他：创建信用卡时，创建对应类型的负债
   - 统计：负债数量，负债金额

6. 财务健康状况

   对个人财务的健康状况进行分析

   内容：

   - 总资产
   - 总负债
   - 净资产
   - 月度现金流
   - 月度结余
   - 债务收入比
   - 资产负债率
   - 资产增长率
   - 趋势图

7. 财务沙盒推演

   - 情景：
     - 失业维持时长
     - 债务利率上涨
     - 股票/基金下跌
     - 每月多存流动资金
     - 提前还清负债
     - 收入上涨
     - 收入下降
     - 大额一次性支出
     - 新增负债
     - 新增资产
     - 投资变现
     - 应急金不足
     - 固定支出增加
     - 被动收入增加
     - 其他可能情况

     以上情景是个人想到的，可能存在情景冲突，有许多未想到的

   - 其他：保存每次推演的设置和结果，方便后续查看

8. 财务知识分享

   - 分类：基础管理，风险管控，投资入门，重大决策，陷阱规避，书籍分享
   - 每一篇发文都需要添加分类，可以有多个分类标签

### 使用什么技术

1. vue全家桶 + typescript + SQLite
2. 数据保存全部在软件中完成，不使用远程服务器
3. 除了知识分享中的发文外，其他内容的数据全部使用数据库技术保存
4. 展示组件应当尽量提取公共内容作为公共组件使用
5. 引入的依赖包应当尽可能的被广泛使用，新引入时应当进行过试运行，保证不影响原有功能
6. 展示页面在不影响功能的情况下应当尽可能美观

### 其他注意

1. 上述描述中的内容中没有添加默认内容，如删除标记，创建时间，修改时间等
2. 上述描述只是进行了功能描述，没有说明需要哪些保存数据，如账户需要入账和出账记录等
3. 金额数字需要做公共的格式化工具
4. 数据库操作应当做统一配置处理，执行数据库操作时应当仅仅返回执行SQL而不实际执行，实际执行应当在业务中自行选择是否使用事务方法执行
5. 上述功能描述并不完整全面，应当做好补充和建议，如支出类型应当区分哪些是必要支出，哪些是额外支出，或者可让用户自定义修改，沙盒推演的每种情景也应当有对应的计算逻辑
