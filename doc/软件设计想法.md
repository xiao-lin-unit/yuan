# 软件设计想法

## 零、设计原则（最高准则）

这份软件的设计，始终把下面四条刻在头顶。任何功能、任何页面，只要违背其中一条，就必须改。

**第一条：用户是零基础的普通人。**

用的人不会看《个人理财规划》，没听说过"净资产""资产负债率"，甚至不知道"公积金"是什么。所以：
- 界面上不出现任何专业术语。要说"你真正拥有的钱"，不说"净资产"；要说"你欠别人的钱"，不说"总负债"。
- 每个数字都要让人一眼看懂它代表什么。余额旁边直接写"这是你卡里现在能花的钱"。
- 不要求用户理解任何概念。软件负责自动算、自动判断，用户只管输入数字。
- 一个功能只在一个地方出现，而且要在用户自然想到它的时候就在眼前。用户不会想"我该去哪个菜单登记这笔还款"——他看到信用卡账单，软件就提示"还一笔"。

**第二条：傻子也能用，找不到就是失败。**

- 打开软件，首页就是今天要用的一切：还剩多少钱、这个月花了多少、有没有要还的、要不要记一笔。不需要点进三四层菜单。
- 记一笔钱只要点一次。点"记支出"或"记收入"，选个类型，填个数，完事。三步，不要弹窗里再套弹窗。
- 功能入口要按"用户会怎么想"来放，而不是按"技术上是哪个模块"来放。用户想"还信用卡"，入口就在信用卡卡片上，而不是藏在"负债→还款操作"里。
- 任何操作都允许反悔。记错了？改。删错了？有回收站。不会弹一句"确定要删除吗"之后就再也找不回来。
- 不用教也会用。不需要说明书，不需要引导视频，打开就能上手。

**第三条：简单，但绝对不能出错。**

- 软件不联网、不绑定银行卡、不碰用户的钱，但它是记账工具——记错了比不记还糟糕。一个用户信任账本说"我还有 5000 块"，结果实际只有 3000，这个软件就是有害的。
- 所有数字必须前后对得上。账户余额 = 初始余额 + 收入 - 支出 + 转账调整 ± 买东西换出去/换回来的钱 + 余额调整，这个等式永远成立，不允许出现任何例外。
- 同一笔钱只在一个地方记一次。任何两处显示同一个数，来源必须唯一：一处是账本，另一处只能跟着看，不允许两处都能改。
- 自动算的东西要让人看得见是怎么算出来的。"你这个月结余 2000"旁边要能展开看"收入 8000 减支出 6000"，而不是一个黑箱数字。
- 用户输入的东西要兜底。填了负数？提醒。选了"从储蓄卡花"，但卡里钱不够？提醒，但不拦着（用户可能就是在登记昨天的账）。
- 软件不联网，凡是用户手填的价、按卡规则估的利息，都要标明"这是你 X 天前填的""估算，以账单为准"，绝不假装是查来的准数。
- 数据不允许丢。任何时候闪退、断电、手滑，已经记过的账必须还在。

**第四条：功能要详细且完善。**

简单不等于简陋。要让用户用过一次就不再想换，每一类钱、每一笔往来、每一种情况都要覆盖到，而且每个细节都要想清楚：什么时候用、谁会用到、用错了会怎样。功能可以藏得深（普通用户用不到就不必看到），但一旦用户需要，必须存在且必须算得对。

## 一、产品定位

### 1.1 这是什么

一个帮普通人管钱的软件。用户把钱的事记进来，软件帮他看清楚：现在手上有多少钱、这个月花了多少、欠了别人多少、哪些钱快到期了、以后会不会没钱花；还要看清楚：哪些东西在给他挣钱、哪些东西每个月在花他的钱、借的钱到底贵不贵。

### 1.2 给谁用

- 从没记过账、不知道自己钱花哪了的人
- 想控制花销、想把欠的钱还完、想攒点钱的人
- 有信用卡、有房贷车贷、有公积金、有股票基金，但不知道怎么统一管理的人
- 有房子、有车、有存款、有理财，但分不清"值钱"和"能花"的人
- 怕麻烦、怕看不懂、怕记错的人

### 1.3 软件承诺

| 承诺 | 具体表现 |
|------|----------|
| 不用联网 | 所有数据存在手机/电脑本地，不上传任何服务器 |
| 不碰你的钱 | 不绑定银行卡、不代付、不代扣、不读短信、不读通讯录 |
| 不怕记错 | 随时改、随时删、有回收站、有历史修改痕迹 |
| 不怕闪退 | 记一笔就立刻存一笔，不会白记 |
| 不用动脑 | 软件自动算、自动提醒、自动归类，用户只管填数字 |
| 不用天天盯价格 | 买的时候填一次、卖的时候填一次，平时不用管涨跌，卖出时一次算清赚没赚 |

## 二、总览：软件里有什么

软件一共六个大板块。每个板块解决一件事：

| 板块 | 解决什么 | 用户一句话理解 |
|------|----------|----------------|
| 账户 | 我手上现在有哪些钱、哪些能花 | "我有哪些卡和账户" |
| 记支出 | 钱是怎么花出去的 | "我花了什么" |
| 记收入 | 钱是怎么进来的 | "我挣了什么" |
| 资产 | 除了卡里的钱，我还值什么、哪些在给我钱、哪些在拿我钱 | "我除了手上的钱，还有什么值钱的" |
| 负债 | 我欠了什么、这钱贵不贵、什么时候还 | "我欠了什么" |
| 分析与推演 | 现在的状况怎么样，将来会不会没钱 | "我现在的钱够不够，以后会怎样" |

外加一个**知识**板块，放一些理财常识文章，跟钱无关，不存任何数据。

> 用户不用理解"资产""负债"这些词。软件用大白话，比如"你值多少钱""你欠多少钱"。

### 2.1 软件里有两本账（用户不用知道，但设计不能混）

这两本账回答的是两个完全不同的问题，必须分开算、分开显示：

| | 回答什么 | 怎么算 | 界面上叫什么 |
|---|----------|--------|--------------|
| 家底账 | "我现在值多少钱" | 某一时点：把所有东西加起来，再减去欠的 | "真正属于你的钱" |
| 流向账 | "我会不会越来越有钱" | 一段时间：每月进 − 每月出 | "每月自动进来的钱""每月自动出去的钱""不上班也能剩多少" |

**规矩**：

- **不强迫用户给东西"站队"。** 同一套自住房，在家底账里是值钱的东西，在流向账里是"每月从口袋拿走 3000 块"的东西。软件在两张卡片上分别显示，不要求用户判断它到底算哪边，更不允许把自住房登记进"负债"模块——那会让"一共欠多少"凭空多出一百万，家底账直接错掉。
- **界面永不出现"资产""负债""净资产""现金流"这些词。** 每个数字都标明自己属于哪本账：「真正属于你的钱」旁边写"这是把房子、存款、投资都算进去的总账，不是你能马上花的钱"；「现在能花的钱」旁边写"这才是你卡里能直接花的"。
- **每一项资产都多带三个字段；每一笔债对应地用"这个月要还多少、其中多少是白给银行的"表达它拿走的钱**（这是把"钱往哪流"落进软件的最小改动）：

| 字段 | 界面上写 | 填什么 | 谁来算 |
|------|----------|--------|--------|
| 每月进 | "它每个月给你多少钱" | 租金、利息、分红、债息；没有就填 0 或留空 | 用户填一次，之后收到钱时自动累计 |
| 每月出 | "它每个月要你花多少钱" | 物业费、保险费、管理费、保养、停车、维修摊到每月 | 用户填一次，可随时改 |
| 净流向 | "它到底是给你钱还是拿你钱" | 自动 = 每月进 − 每月出 | 软件算，界面只显示一句人话 |

**关键边界（防止重复计算）**：「每月出」只填这项东西**自己的**持有成本，**不填这套房贷的月供**。融资成本一律由负债模块统一算，否则一套房的钱会被扣两遍。软件在字段旁边直接写死一句提示："借钱的月供不用填在这儿，那笔在『我欠的钱』里算过了。"

## 三、账户：我手上现在有哪些钱

### 3.1 为什么要有"账户"

很多人家里有储蓄卡、有现金、有微信零钱、有信用卡、还有公积金。它们性质完全不同：储蓄卡里的钱能直接花，公积金里的钱得符合条件才能动。软件要区分清楚，否则"总资产"会算错——把公积金也当成能花的钱，用户以为自己有钱，其实取不出来。

### 3.2 三类账户

| 类型 | 这是什么 | 能不能直接花 | 典型例子 |
|------|----------|--------------|----------|
| 流动资金账户 | 钱能自由花 | 能 | 储蓄卡、现金、微信、支付宝 |
| 信用卡账户 | 先用后还的钱 | 是花银行的，要还 | 信用卡 |
| 其他资金账户 | 特殊用途、受限的钱 | 不一定 | 公积金、社保、美容卡、礼品卡、已冻结的存款 |

### 3.3 流动资金账户

**存什么信息**：账户名字（自己起，比如"工资卡"）、是什么类型（储蓄卡/现金/微信/支付宝）、里面现在有多少钱、备注（可选，比如"这张卡存房租"）。

**关键约定**：
- 这类账户的钱**默认为是能自由花的**，用户改不了这个设定。因为从定义上它就能自由花，改了就没意义。
- "备注"完全可选，不填也没关系。
- 用户想看看"我现在能花的钱一共有多少"，软件就把所有流动资金账户的余额加在一起显示。

**典型用法**：用户有 3 张储蓄卡、200 块现金、微信里 800，软件把它们都登记上，随时看总和。

### 3.4 信用卡账户

**存什么信息**：账户名字、类型固定为"信用卡"、总额度（这张卡最多能花多少）、已用额度（已经花了多少）、可用额度（还能花多少，自动算）、账单日（每月几号出账单）、还款日（每月几号要还）、关联一个用来还款的储蓄卡、备注。

**还清一笔账单要用到的规则（新增，按这张卡自己的章程填，不是全国统一的数）**：记账日、免息期天数、最低还款额规则、日利率、计息方式（全额计息 / 只按未还部分计息）、是否按月复利、容时容差、取现是否免息、分期手续费规则、违约金规则。

**关键约定**：
- 已用额度怎么来：用户每用信用卡记一笔支出，就自动累加到已用额度；每还一笔，就扣减。用户**不用手动填**，软件自动管。
- 可用额度 = 总额度 - 已用额度，自动算。
- **信用卡不计入"现在能花的钱"**。界面单列一行："还能刷 X 元 —— 这不是你的钱，刷了就要还。"信用额度是银行的钱，不是用户手上的钱。
- 关联还款账户：用户选一张储蓄卡作为还信用卡的钱从哪出。这样到期时软件知道提醒他从哪张卡扣。
- **自动创建对应负债**：一旦用户建了一张信用卡，软件同时在"负债"里建一条对应的欠款记录，额度就是欠款。用户在信用卡上花钱，负债也跟着动。用户不用管两遍。
- 信用卡从刷卡到还清的完整算法见 7.7：全额还清、只还最低、办分期、只还一部分、逾期、取现，六种情况各有各的账，不能只当"刷了就加、还了就减"。

**还款提醒**：还款日临近时（比如提前 3 天），在首页醒目位置提示：

> "你的 XX 信用卡还有 3 天要还 8,000 元，将从 XX 卡扣款。全额还清没有利息；只还最低 800 元，下个月大约会多出 235 元利息。"

### 3.5 其他资金账户（重点改动）

这类账户放的是**不能随便花**的钱。但"不能随便花"不等于"完全不能花"——它往往有特定用途。比如：

- 公积金：可以拿来付房租、可以拿来装修，但**不能**拿来买零食、吃三餐
- 美容卡：只能用在美容消费上
- 单位发的礼品卡：可能只能在特定商家用
- 社保账户：基本不能动
- 已冻结的存款：暂时取不出来

**所以这类账户要允许绑定"能用的支出类型"。**

**存什么信息**：账户名字、类型（储蓄卡/现金/微信/支付宝/社保/公积金/其他）、里面有多少钱、流动资金设为"否"（默认；社保公积金强制为否且不可改，其他类型用户可手动改）、**能用来付哪些支出类型**、备注。

**绑定支出类型的规则**：
- 用户给这个账户勾选几个支出类型，意思是"这个账户的钱只许花在这些地方"。
- 举例：公积金账户勾选"房租""装修"→ 记一笔"房租"支出时，可以选择从公积金扣；记"三餐"时，下拉列表里**不会出现**公积金账户。
- 这个规则是**软约束**，不是硬拦截：如果某个支出类型没被任何受限账户勾选，就照常从流动资金账户里选。用户某次确实想破例用受限账户，可以在支出记录的高级选项里临时选择，但会标记"非绑定用途"，在统计里单独提示。
- 社保账户默认不绑定任何支出类型，且不可编辑绑定（因为它基本无法支取）。
- 一个支出类型可以被多个受限账户绑定（比如"医疗"既可以用医保账户，也可以用现金）。

**不绑定也能用**：如果用户嫌麻烦，完全可以不设绑定，所有账户都随意选。绑定是"精细管理"的可选项，不是必填。

**与资产页的关系**：这类账户是唯一账本，资产页里对应的一条只是**只读镜像**（见 6.2）。用户改账户，镜像跟着看；不允许在资产页反改账户余额；账户被删/归档时镜像标"已断开"，保留当时的数但不再参与总账，提示重新关联。

**典型场景**：
> 小王有个公积金账户，他把它绑定了"房租"。每个月记房租时，支出账户那里下拉就直接显示"公积金账户"，记完之后公积金余额自动减、支出统计里也有这笔。而记午餐时，下拉里只有储蓄卡和微信，不会出现公积金。小王完全不用操心"我该不该用公积金付午饭"这种问题——软件直接替他过滤了。

### 3.6 账户统计

用户打开账户页面，顶部一目了然地看到：

| 看板数字 | 怎么算 | 大白话解释 |
|----------|--------|------------|
| 现在能花的钱 | 所有流动资金账户余额之和 | "你手上的现金和卡里能直接花的钱" |
| 暂时动不了的钱 | 所有其他资金账户余额之和 | "公积金、社保、冻结的钱，有条件的才能动" |
| 还能刷的额度（不是你的钱） | 所有信用卡可用额度之和 | "银行的钱，刷了就要还，不算你手上的钱" |
| 欠银行的钱 | 所有信用卡已用额度之和 + 其他贷款剩余本金 | "你刷信用卡、借贷款，还没还的" |
| 借进来的钱 | 所有被标记为"亲友借款"的负债 | "别人借给你的钱" |
| 借出去的钱 | 所有被标记为"借给亲友"的资产 | "你借给别人的钱" |
| 真正属于你的钱 | 全部资产 − 全部负债（一次减完，公式见 10.9） | "把你所有东西加起来，再减去你欠的，剩下的" |
| 留够应急金后，还多出来多少 | 现在能花的钱 −（你设的要留几个月 × 每月必须花的钱）；不够留就显示"还差 X 元" | "留够急用的，剩下的才是能动脑筋的钱" |
| 不上班也能撑住多少 | 稳稳每月进来的钱 ÷ 每月必须花的钱（见 2.2、8.1.1） | "就算不去上班，这些进账能顶掉多少开销" |
| 变化趋势 | 按**月末存一次数**看这个数字怎么变 | 一条折线图；之后改了价、改了口径都不改历史。点开看"这个月多出来的钱是怎么来的"（见 8.1.4） |

> "真正属于你的钱"就是传统意义上的净资产，但界面上绝不会出现"净资产"三个字。
>
> 上面「欠银行的钱」「借进来的钱」「借出去的钱」三行只是让用户看清楚钱都在哪，**不再额外加减一次**——它们已经包含在「全部资产」「全部负债」里了，再加一遍就是同一笔钱算两遍。
>
> 新增的「留够应急金后，还多出来多少」「不上班也能撑住多少」都是**只读行**：不新增账户字段、不新增录入动作，只把已有数字和 4.2 / 6.3 的标记算一遍（见 13.2、13.11）。

### 3.7 账户的辅助能力

- **账户间转账**：比如从储蓄卡往信用卡还款。记一笔"转账"，选从哪张卡转出、转到哪张卡、多少钱。两张卡的余额自动一减一加，负债那边也同步更新（如果是还信用卡，已用额度扣减）。用户不用分别记一笔支出和一笔收入。还款转账要分清本金与利息：本金只是把现金换成"少欠一点"，利息是真花掉的钱（见 7.12）。
- **资产买卖的现金收付**：买股票基金、卖股票基金、买房买车，钱从哪张卡出去、回到哪张卡，都走同一本账户流水，但**不记成支出或收入**（见 6.5），避免"刚买完基金，这个月支出突然多了 2 万"。
- **先给自己留一笔**（见 13.3）：工资到账那天可一键记一笔转账到用户指定的储蓄账户，复用本节的转账能力，**不新增账户类型、不新增表字段**；软件不碰钱，只做提示与代记。
- **账户归档**：很久不用的卡可以"归档"，归档后不出现在日常列表，但历史记录保留。想恢复随时恢复。
- **拖拽排序**：账户在列表里的顺序，用户按住拖动就能调。
- **记账流水**：每张卡底下都能看到它的流水明细——什么时候进了一笔、什么时候出了一笔、进出后余额变成多少。这是核对账目是否准确的关键，用户随时可以翻出来对账。流水明细分为入账和出账，在每张卡下分别展示。

### 3.8 防止出错的措施

- 账户余额是"算"出来的，不是"填"出来的。除非是开户时的初始余额，否则余额一律由记账自动增减。避免用户手动改余额导致和实际不符。
- 用户非要手动改余额（比如发现账对不上，想强制调平），可以走"余额调整"操作，但必须填原因，且会在流水里留下"调整"记录，方便事后追溯。
- 删掉一个账户前，如果里面还有余额或关联记录，必须提示"这个账户下还有 XX 笔记录，删除后这些记录仍会保留但不再关联账户"，确认后才删。
- 账户页是现金与受限资金的唯一写入点：资产页里由账户生成的只读镜像、负债还款关联的扣款账户，都不允许反改余额。
- 账户余额是**按当时填的数记下的钱数**，软件不会因为它"以后不经花"就自动把它调小；"钱越来越不经花"只在 8.2 的推演里作为一个可选假设出现（见 13.1），真实账本永远是名义金额。

## 四、记支出：钱是怎么花出去的

### 4.1 支出分类（扁平化，只一层）

**不再分"一级/二级"**。原来的设计里"餐饮美食"下面再分"三餐/零食/外卖"两层，用户每次记一笔要选两次，麻烦且容易懵。现在**只有一个层级**：直接选类型，一步到位。

**预设类型**（用户可自己加、可改名字、可删掉不用的）：

三餐、零食饮料、水果、外卖、买菜做饭、水电燃气、物业、房租、话费网费、看病买药、日用品、交通、加油、打车、衣服鞋帽、美容护肤、教育学习、书报杂志、孩子花销、孝敬长辈、宠物、人情往来、娱乐休闲、旅游出行、烟酒、健身运动、家居装修、电器数码、保险、税费、其他。

> 一共二十多个，不多不少。用户记一笔，点开下拉，一眼看到"三餐"，点一下就完事，不用再进一层。

### 4.2 分类是"必要"还是"弹性"：不预设，让软件学

**取消掉"三餐是必须的、零食不是"这种硬性划分**。因为同一件事对不同人意义完全不同：对天天做饭的人是"三餐"，对外卖党是"外卖"，对健身的人是"必要营养"，对想省钱的人是"可省开支"。**由用户自己定义什么对他来说是"必须花的钱"**。

- 软件预设所有分类为"未分类"。
- 用户在设置里可以对每个分类打一个标记：这是"必须花的钱" / "可以省的钱"。
- 也可以完全不打，软件就不参与这个判断。
- "必须花的钱"有什么用：算"紧急备用金够不够"时要用到——软件需要知道你一个月**最低**要花多少，才能判断你失业了能撑几个月。

**系统会默认给出一个推荐，但不强制**：比如第一次使用时提示"我们建议把'房租''水电''看病'等标记为必须花的钱，你觉得呢？"用户一键接受、逐项改、或者跳过都行。

### 4.3 记一笔支出要填什么

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 花了多少钱 | 只填数字，软件自动加货币符号和千分位 | 必填 |
| 花在哪（支出类型） | 从扁平列表里挑一个 | 必填 |
| 什么时候花的 | 默认"现在"，可改日期时间 | 必填，默认当前时间 |
| 从哪个账户付的 | 下拉选账户。受限账户的过滤规则见 3.5 | 必填 |
| 付给谁（可选） | 商家名、人名 | 可选 |
| 备注（可选） | 随便写 | 可选 |
| 小票照片（可选） | 拍照或选图，用于报销核对 | 可选 |
| 这条能报销吗 | 标"能"，单独归到"待报销"清单 | 可选 |
| 标签（可选） | 用户自己加的标签，比如"出差""过年" | 可选 |

**记一笔的完整动作**：首页点"记支出" → 输入金额 → 选类型 → 选账户 → 点"保存"。最多 5 秒。

### 4.4 支出的自动行为

- 保存后：对应账户余额**立刻**减少（除非是信用卡，则已用额度增加）。
- 该账户的流水里**立刻**多出一条记录，显示交易后余额，方便随时对账。
- 如果是信用卡支出：同时更新负债模块里对应信用卡的"剩余本金"。
- 如果标记为"能报销"：进入"待报销"清单，同时记一笔"借出去、还没收回来的钱"（见 6.2 的 A3）。报销到账时按**冲减**处理，不记成收入、不计入"这个月一共挣多少"（见 5.4），该笔支出标记为"已报销"，不重复计入支出统计。
- 如果选了受限账户且不是其绑定用途：标记"非绑定用途"，在账户统计页提示。
- 借钱产生的利息与手续费会生成一条类型为"借钱的成本"的支出，默认计入"这个月一共花了多少"；设置里可关，关了要在旁边注明"关掉后，这个数会少算一部分真花掉的钱"（见 7.12）。

### 4.5 支出统计

用户点进"支出"，看到：

| 统计 | 说明 |
|------|------|
| 这个月一共花了多少 | 当月全部支出合计 |
| 这个月还剩多少能花 | 本月预算（若设了）减已花 |
| 本周花了多少 | 本周一到周日合计 |
| 这个月每天花多少 | 柱状图，哪天花得多一眼看出 |
| 花在哪最多 | 饼图，各类支出占比，最大的一块标红 |
| 和上个月比 | 多了还是少了，差多少 |
| 必须花的钱 vs 可省的钱 | 根据用户的分类标记汇总 |
| 哪些支出能报销还没报 | 待报销清单 |

### 4.6 辅助能力

- **重复支出**：每月固定那几笔（房租、话费、会员）设一次"每月自动记"，之后每到时间自动生成一条，用户确认即可。免去每月手记。
- **快速记**：首页保留最近用过的 5 个类型和 3 个账户，一键复用。
- **发工资那天先留一笔（见 13.3）**：设置里填"每月先留多少""留到哪张卡"；工资到账时首页提示"先把 X 元留起来，剩下的再花"，一键记一笔转账（复用 3.7 的转账）。软件不碰钱、不自动转账、不替用户决定留多少；统计里显示为"这个月先给自己留了多少"。
- **修改与删除**：记错了，进详情直接改；删掉进回收站，30 天内可恢复，过期自动清理。
- **预算提醒**：为某个支出类型设了月预算后，花到 80% 时提示，花超时明显标红。

### 4.7 防止出错的措施

- 金额只能填正数，填了负数或 0 直接拦下并提示。
- 填了金额却忘了选类型/账户，保存时高亮提醒"还差一个"，不让产生不完整记录。
- 选的账户余额不足时，保存成功但给一条橙色提示"该账户余额不足，是否确认？"——不阻止（可能是补记昨天的账），但用户心里有数。
- 同一时间、同一金额、同一账户的重复记录，提示"刚刚已经记过一笔相同的，是不是手滑了？"——可忽略。

## 五、记收入：钱是怎么进来的

### 5.1 收入分类（扁平化，只一层）

**同样只有一层，直接选**：

工资、奖金、兼职外快、投资收益（利息/分红/租金等）、退款退货、报销到账、礼金红包、二手变卖、中奖、其他。

### 5.2 收入稳定性：同样由用户定义

原来"工资是稳定的、兼职是不稳定的"这种预设取消。用户可以在设置里标记哪些收入是"每月都有的"、哪些是"偶尔才有"。

- "每月都有的"用来算**每月固定能拿到的钱**，是判断现金流是否健康的重要依据。
- 如果不标记，软件就不判断。

### 5.3 记一笔收入要填什么

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 收入多少钱 | 只填数字 | 必填 |
| 是什么收入 | 从列表选类型 | 必填 |
| 什么时候收的 | 默认现在 | 必填，默认当前时间 |
| 进哪个账户 | 钱打到哪张卡/哪个账户 | 必填 |
| 谁给的（可选） | 公司名、人名 | 可选 |
| 要不要报税 | 标记一下，方便汇总 | 可选 |
| 备注、标签 | 可选 | 可选 |

### 5.4 收入的自动行为

- 保存后：对应账户余额立刻增加。
- 流水里立刻多出一条。
- 如果该笔是"报销到账"，自动关联到之前标记的"待报销"支出并销账。**它是把之前垫的钱收回来，属于冲减，不是新挣的钱**：不计入收入统计、不计入"每月固定能拿到的钱"、不影响偿债比例；待报销清单与"借出去、还没收回来的钱"同步减少。
- 卖股票基金到手的钱、借入的钱、账户间转账，都**不算收入**（见 6.5、7.12、3.7），避免"这个月一共挣多少"虚增。

### 5.5 收入统计

| 统计 | 说明 |
|------|------|
| 这个月一共挣多少 | 当月收入合计 |
| 本周挣多少 | 本周合计 |
| 这个月每天挣多少 | 按天汇总 |
| 挣得最多的是哪类 | 饼图 |
| 和上个月比 | 涨了还是跌了 |
| 每月固定能拿到的钱 | 根据用户的稳定性标记汇总 |
| 不用上班也能挣的钱 | 投资收益、租金等被动收入，占比越高说明财务越自由 |

### 5.6 辅助能力

- 工资类收入可设"每月自动记"，到日子自动生成；同时按 4.6 的「发工资那天先留一笔」给一句提示，用户点一下才记，软件不自动转账。
- 收入与资产进账的"稳不稳"按 5.2 与 6.3 的标记统一管理：只有两处都标"每月都有"的，才进"稳稳每月进来的钱"（见 13.2）。
- 修改/删除/回收站：同支出。

### 5.7 防止出错的措施

- 金额只能填正数。
- 必填项缺失不让保存。
- 选的账户被删除了？该记录保留，但账户字段显示"（已删除的账户）"，提示用户重新关联。

## 六、资产：除了卡里的钱，我还值什么、哪些在给我钱

### 6.1 为什么要有资产

账户里放的是"现金和类现金"，但很多人还持有股票、基金、公积金、借给朋友的钱、自住房、车子、黄金。这些也是"值钱的"，但不像现金那样随手能花。软件要把它们算进"把所有东西加起来，再减去欠的"，同时标清楚"现在能变现多少""要多久才能拿到"，还要按 2.1 的流向账说清楚"它每个月是给你钱，还是拿你钱"。

**用户看到的是一排图标，只选一次，不进二级菜单**（遵守 10.5 的扁平原则）。选完某一类，表单自动展开这一类专属要填的几项，其余字段藏起来。界面问的是："你新增的是什么？"

### 6.2 资产大类（平铺，只选一次）

| 编号 | 界面上的名字 | 都包含什么 | 由谁提供金额 |
|------|--------------|------------|--------------|
| A1 | 卡里和手上的钱 | 活期、定期、大额存单、现金、微信、支付宝 | **账户模块，只读汇总** |
| A2 | 取出来有条件 / 暂时动不了的钱 | 公积金、社保、医保账户、冻结存款、储值卡、礼品卡、押金保证金 | **其他资金账户，只读镜像** |
| A3 | 借出去、还没收回来的钱 | 借给亲友、应收退款、押金、待报销款 | 资产模块登记 |
| A4 | 股票 | 上市股票、ETF | 买卖记录自动算 |
| A5 | 基金 | 货币 / 债券 / 股票 / 指数基金 | 买卖记录自动算 |
| A6 | 别的投资 | 国债、债券、银行理财、券商理财、保险现金价值、年金 | 买卖记录自动算 |
| A7 | 房子、车位、商铺、土地 | 自住房、出租房、商铺、车位 | 资产模块登记 |
| A8 | 车和交通工具 | 汽车、摩托、电动车 | 资产模块登记 |
| A9 | 值钱的物件 | 黄金、首饰、收藏、名表、数码设备 | 资产模块登记（可关掉不计入） |
| A10 | 生意和股份 | 个体户、公司股权、分红权、版权专利 | 资产模块登记 |
| A11 | 其他 | 用户自己起名 | 资产模块登记 |

**A1、A2 是重点**：这两类**不允许在资产页新建、不允许编辑金额、不参与资产页的求和公式**。资产页顶部给两块只读卡片——"你卡里一共有 X 元""你还有 X 元暂时动不了"，点进去跳到账户页。这样既让用户一眼看到全貌，又彻底消掉"同一笔公积金在账户和资产里各算一次"的错误。

**受限资金的联动（替代原设计）**：原设计是"创建社保、公积金这类资产时必须同时创建对应账户，之后两边都能改、改一处另一处跟着变"。现在改为：**在账户页建公积金账户，资产页自动生成一条只读镜像；账户为主、镜像只读，禁止反向写回**。社保账户默认不绑定任何支出类型，且不可编辑绑定（见 3.5）。用户不用理解"联动"这个词，他只会觉得"在卡那边改了，这边也跟着变了"。

### 6.3 所有资产共用的字段

| 字段 | 界面上写 | 必填 | 说明 |
|------|----------|------|------|
| 名字 | 给它起个名 | 是 | "出租的那套小房""借给老张的钱" |
| 属于哪类 | 这是什么 | 是 | 6.2 的平铺大类，只选一次 |
| 当时花了多少 | 买它一共花了多少 | 是 | 含税费、手续费、中介费；自动带出，可改 |
| 哪天买的 | 什么时候买的 | 是 | 默认现在 |
| 现在值多少 | 现在大概值多少 | 否 | **默认不填**，见 6.4 估值规则 |
| 这个值什么时候填的 | 上次更新是 X 天前 | 自动 | 沿用原 6.7 |
| 值怎么来的 | 按买入价 / 按上次买卖价 / 你自己填的 | 自动 | 用户可切换，切换留痕 |
| 每月进 | 它每个月给你多少钱 | 否 | 租金、利息、分红（2.1 的流向账） |
| 这笔进账稳不稳 | 每月都有 / 偶尔有 / 说不准 | 否 | 只有"每月都有"参与"不上班也能撑住"与压力测试（见 13.2）；不标记就按"说不准"处理，只展示、不参与判断 |
| 每月出 | 它每个月要你花多少钱 | 否 | 持有成本，**不含借款月供** |
| 净流向 | 它给你钱 / 它拿你钱 / 不进不出 | 自动 | 2.1 的流向账最小单元 |
| 多久能变成现金 | 随时 / 几天 / 几个月 / 很难 / 动不了 | 是 | 对应原 6.6「哪些钱能马上拿出来」 |
| 提前拿会不会扣钱 | 提前取要扣多少 | 否 | 定期、基金赎回费、房产交易税费 |
| 钱从哪个账户出去的 | 用哪张卡买的 | 否 | 买了之后该账户余额自动减少 |
| 跟哪笔债有关 | 这笔钱是借来买的吗 | 否 | 指向负债记录，见 7.12 |
| 算不算进总账 | 要不要算进"真正属于你的钱" | 是 | 默认算；车、数码等可关 |
| 备注、照片、凭证 | 随便写 / 拍个照 | 否 | 沿用原设计 |

### 6.4 估值规则：不逼用户天天更新

这是本次改动的核心：**买入时输入价格和数量，卖出时输入价格和数量，最终计算即可；平时不用每日更新股票盈亏多少、基金盈亏多少**。落成四条规则：

1. **默认按买入价记。** 买入时填了单价和数量，软件就一直用这个成本价当"现在值多少"，旁边标一句"按买入时算，没算涨跌"。
2. **不估算浮动盈亏。** "一共赚/亏多少"默认只统计**已经卖出落袋**的部分；没更新过价的持仓，不显示"浮盈""浮亏"，也不显示 0，显示"—"并写"还没卖，先不算赚没赚"。
3. **想看现在值多少，自己点一次。** 资产详情页放一个"更新一下现在值多少"，填一次价，之后按这个价算，并标"这是你 X 天前自己填的，软件不联网，不会自动变"。每次更新记下"哪天从多少改成多少"（原 6.4 的价格变动记录），用户想看"我这个月股票是涨是跌"，翻记录就行；历史版本不覆盖。
4. **总账口径可切换，但必须提示。** 设置里可选"保守（按买入价，推荐）"或"按我填的最新价"。切到后者时弹一句白话："这样算出来的总数会跟着你填的价变，不是软件查到的，别拿它当准数。"

> 设计者口径：软件不联网，任何"市值"都是用户输入或成交价推导，不得伪装成实时行情；估值日期必须与数字同屏显示。所有手动填的数字（股价、净值、余额）都有"最后更新时间"，超过 90 天在总账上标一句"有些数是很久以前填的，总账可能不准"。

### 6.5 股票 / 基金 / 别的投资：买入—卖出闭环

A4、A5、A6 共用同一套模型，界面上分别叫"股票""基金""别的投资"，**各自有独立列表和详情页，可以单独管理、单独看自己这一类和每一只的赚亏**；但底层不再是"维护当前价"，而是"记流水、卖出时结算"。

#### 6.5.1 买入要填什么

| 字段 | 界面上写 | 必填 |
|------|----------|------|
| 买的是什么 | 名字 / 代码（代码可不填） | 是 |
| 哪天买的 | 默认现在 | 是 |
| 每个多少钱 | 单价 / 净值 | 是 |
| 买了多少 | 股数 / 份数 | 是 |
| 另外交了多少钱 | 佣金、申购费、印花税等 | 否，默认 0 |
| 钱从哪张卡出 | 关联账户 | 是 |
| 备注 | 随便写 | 否 |

保存时弹出一句确认：**"一共从卡里出去 X 元，对吗？"**（X = 单价 × 数量 + 费用）。

**自动行为（守恒的关键）**：
- 关联账户余额 −X，账户流水多一条"换成了 XX"，不属于任何支出类型；
- **不生成支出记录**，"这个月一共花了多少"不增加；
- 生成一条"买入批次"，记下日期、单价、数量、费用、剩余数量；
- 该标的详情页"买卖记录"里立刻可翻到这一条。

#### 6.5.2 卖出要填什么

| 字段 | 界面上写 | 必填 |
|------|----------|------|
| 哪天卖的 | 默认现在 | 是 |
| 每个多少钱 | 成交单价 / 净值 | 是 |
| 卖了多少 | 股数 / 份数 | 是 |
| 另外扣了多少钱 | 佣金、赎回费、印花税等 | 否，默认 0 |
| 钱回到哪张卡 | 关联账户 | 是 |

保存时确认：**"这次到手 X 元，对吗？"**（X = 单价 × 数量 − 费用）。

**自动行为**：
- 关联账户余额 +X，流水多一条"XX 换回钱"；
- **不生成收入记录**，"这个月一共挣多少"不增加（否则收入虚增，会影响偿债比例和结余判断）；
- 按剩余批次算出这次卖掉的成本，**当场结算已落袋的赚亏**；
- 部分卖出后，剩余持仓成本、数量自动更新；全卖完自动标"已清仓"，记录保留可查。

#### 6.5.3 结算规则（设计者口径）

- 成本计价默认**移动加权平均**，界面解释一句"把几次买的价钱平均一下"；设置里可改"先买进的先卖出"，改了留痕，历史结算**不重算、不覆盖**。
- `本次成本 = 卖出数量 × 当前平均成本`，`本次到手 = 成交价 × 数量 − 费用`；
- `这次赚/亏 = 本次到手 − 本次成本`（费用已含在到手与买入成本里，不漏算）；
- 清仓时给一句人话总结，就是"最终计算即可"：
  > "这只前后 1 年 3 个月，一共赚了 2,500 元，相当于每年约 8%。"
  （按资金占用时间折算，界面不出现"年化""XIRR"字样）
- 标的详情页展示三块：**买卖记录**（每笔日期、单价、数量、费用、到手/付出）、**已经落袋的赚亏**（逐笔 + 合计）、**还没卖的部分**（数量、成本、按买入价算的值）。

#### 6.5.4 必须覆盖到的情况

| 情况 | 软件怎么做 |
|------|------------|
| 多次买入、分次卖出 | 批次表逐笔扣减，任何时点持仓数量 = Σ买入 − Σ卖出，不为负 |
| 分红 / 派息 / 利息到账 | 记一笔收入进关联账户，同时自动累计到该标的"它每个月给你多少钱"；**不冲减持仓成本** |
| 分红再投 / 基金红利再投 | 自动变成一笔新的"买入"，单价用当日净值，费用 0 |
| 送股、转增、份额拆分 | 数量调整、总成本不变，留一条"哪天数量从 X 改成 X，原因：送股" |
| 基金锁定期 / 封闭期 | 到期前几天提示"你的 XX 基金快可以赎回了"；锁定期内点"卖出"给提示但不硬拦 |
| 卖出到账要等几天 | 填"几天到账"，未到账前显示"在路上 X 元"，不计入"现在能花的钱" |
| 卖的数量比持有的多 | 拦下并提示"你一共只有 X 份"，不产生负持仓 |
| 填了 0 或空的价格 | 拦下；不允许把"不知道价格"记成 0 元 |
| 关联账户被删 | 记录保留，显示"原来那张卡已删除"，提示重新关联；不自动改历史金额 |

### 6.6 房子、车位、商铺、土地

不动产和股票完全不同：**金额大、流动性差、买卖一次要交不少钱、还常常连着一笔贷款**。在家底账里它是值钱的东西；在流向账里，自住房是每月拿走钱的东西，出租后租金扣完月供和杂费还有剩，才开始给你钱。所以单独一套字段。

| 字段 | 界面上写 |
|------|----------|
| 是自住还是出租 | "自己住 / 租给别人 / 空着 / 做生意用" |
| 买的时候一共花了多少 | 含首付、税费、中介费 |
| 现在大概值多少 + 什么时候估的 | 默认按买入价，可一年更新一次 |
| 每个月的租金 | 自住填 0 |
| 每个月要交的钱 | 物业、保险、维修摊月、供暖、车位费（**不含月供**） |
| 借了多少钱买的 | 关联到房贷那条负债，自动带出 |
| 现在还欠多少 | 从负债自动带出，只读 |
| 押在银行 / 有没有房产证 | 备注 + 凭证照片 |
| 卖一次大概要交多少 | 中介费、税费估算，用于"提前拿会不会扣钱" |
| 多久能卖掉 | 默认"几个月"，用户可改 |

**自动给出的三句人话**（这就是流向账落地的样子）：

- 自住房："这套房在总账里值 100 万，但它每个月从你口袋拿走 3,000 元（物业 500 + 房贷利息 2,500）。"
- 改成出租、月租 4,500："租金扣掉月供和杂费，每月给你多留 1,500 元，它开始给你钱了。"
- "真要急用钱，这套房大概要几个月才能变成现金，还要扣掉约 X 元的费用。"

> 设计者口径：房贷月供中"本金"部分不是费用，只是把现金换成房子的净值；"利息"才是真消耗。月供不在资产侧重复记为持有成本，也不把本金部分算进"每月出去的钱"。

### 6.7 车、贵重物件、生意股份、借出去的钱

| 类别 | 专属字段 | 特别规则 |
|------|----------|----------|
| 车 | 买入价、上牌年月、现在大概值多少、每年大概掉多少价、每月养车花多少 | 默认"算进总账"但提示"车一年比一年不值钱"；金额只许正数 |
| 贵重物件 | 买入价、现在大概值多少、放在哪、有没有凭证 | 默认**不计入**总账，用户可一键打开（避免把日常消费品当财富） |
| 生意股份 | 投了多少、占多少、去年分了多少钱、现在大概值多少 | "每月进"按最近一次分红折算，标注"不是保证有的" |
| 借出去的钱 | 借给谁、哪天借的、说好什么时候还、要不要利息、收回来多少、还剩多少 | 新增状态"已收回 / 部分收回 / 可能收不回"；标记"可能收不回"时软件提示"要不要先不把它算进总账"，由用户决定，不擅自改数 |

### 6.8 资产的统计

| 界面上的名字 | 怎么算 |
|--------------|--------|
| 把所有东西加起来值多少 | 账户余额 + 各类资产估值（A1/A2 只读汇总，不重复加） |
| 其中能马上拿出来多少 | 按"多久能变成现金"分组：随时 / 几天 / 几个月 / 动不了 |
| 已经落袋赚了多少 | 全部已卖出结算的赚亏合计 |
| 还没卖的，本钱是多少 | 全部持仓成本合计（**不显示浮动盈亏**，除非用户更新过价） |
| 每月自动进来的钱 | Σ 各项资产"每月进" |
| 其中稳稳每月都有的 | Σ 标记为"每月都有"的那部分（见 13.2） |
| 每月自动出去的钱 | Σ 各项资产"每月出" + Σ 各笔债每月利息与费用 |
| 不上班也能剩多少 | 上面两项相减，负数标红 |
| 真要全变成现金，一共要扣多少 | Σ 各项资产"提前拿会不会扣钱" + 房产"卖一次大概要交多少" + 投资赎回费（见 13.7） |
| 哪些在给你钱 / 哪些在拿你钱 | 按净流向分成两张清单，自住房、车会出现在"拿你钱"那张里 |
| 钱主要压在哪 | 饼图，按大类；"房子"占比过高时给一句白话提示 |
| 钱和进账是不是都压在一处 | 一套房占总资产、一份工资占总进账的比例；过高时给一句白话提示（见 13.8） |

> 界面上不出现"被动收入占比""流动性""折旧""现金流""集中度"等词，全部用上表的说法。
>
> 「真要全变成现金，一共要扣多少」是**估算**，旁边固定写"这是你填的手续费和税费加起来的，真卖的时候可能不一样"；8.2.2 的「把投资换成现金」情景直接取这个数（见 13.7）。

### 6.9 防止出错的措施

- 金额、单价、数量、股数、份额一律正数；录入时 0 与空都拦下，不允许"不知道"被记成 0。若历史记录里确实缺估值，展示层显示"—"，不报错、不显示 0（避免用户误以为市值为 0）。
- 卖出数量不得超过持仓；买入/卖出的账户余额不足时橙色提示但不拦（可能是补记昨天的账，沿用 4.7 的精神）。
- 任何"现在值多少"的手填数字都带"上次更新是 X 天前"；超过 90 天在总账上标"有些数是很久以前填的，总账可能不准"。
- 估值口径切换、计价方式切换、成本重算、价格变动，全部留痕，历史结算记录不覆盖。
- 资产与账户镜像关系断开（账户被删/归档）时，镜像标"已断开"，**保留当时的数值但不再参与总账**，提示重新关联；不允许静默沿用旧数。
- 联动账户被删除时：资产保留，提示用户重新关联；两边不再联动，直到重新关联（沿用原 6.7 并加强）。
- 同一标的同一天同金额同数量的重复买入，提示"刚刚记过一笔一样的，是不是手滑了？"可忽略。

## 七、负债：我欠了什么、这钱贵不贵

### 7.1 为什么要有负债

信用卡、房贷、车贷、花呗、借朋友的钱……这些都是"要还的"。如果不单独记，用户只看到账户余额，会误以为自己很有钱，实际欠了一屁股。软件要把"欠的"单列出来，还要帮用户记住"什么时候该还、每期还多少、还完要多久"，更要说清楚"这笔钱到底贵不贵、还完还能不能扛住事"。

**边界（很重要）**：负债模块只登记**有明确债主、明确金额、明确偿还义务**的钱。按 2.1 的流向账，自住房、车也是"每月从口袋拿走钱的东西"，但它们不是欠别人的钱，放在各自的资产卡片上（6.6、6.7），两边在"每月自动出去的钱"里汇总。软件在负债页给一句解释："这里记的是真要还给别人、有账期的钱；自己住的房子每个月要贴的钱，记在那套房子的卡片上。"

### 7.2 负债类型与用途标签

**类型（保留，只选一次）**：房贷、车贷、信用卡、消费贷、装修贷、助学贷、网贷、电商分期、租金分期、借的亲友钱、其他。

**再加一个必填、只需点一下的标签「这钱借来干了什么」**：

| 标签 | 界面上写 | 典型 | 影响什么 |
|------|----------|------|----------|
| T1 | 买房买地 | 房贷 | 关联不动产；利息常为浮动、期限长 |
| T2 | 买车 | 车贷 | 关联车；东西在贬值 |
| T3 | 做生意 / 买了能生钱的东西 | 经营贷、出租房按揭 | 与"每月自动进来的钱"对照，看杠杆是否划算 |
| T4 | 先花了再还 | 信用卡、消费贷、电商分期 | 成本最高，健康分析优先预警 |
| T5 | 应急借的 | 看病、失业周转、家里急用 | 单独标记，是风险信号而非消费问题 |
| T6 | 替别人担的 | 担保、共同借款 | 进"万一要我还的钱"，默认不算进总账 |
| T7 | 亲友之间 | 借亲友钱 | 默认不计息，可手动开启 |

> 设计者口径：按用途而非产品名分类，才能回答"这个家庭是在借钱买会生钱的东西，还是在借钱填已经花掉的窟窿"。这是判断债务质量最关键的一维，也直接决定建议该怎么给。界面上不出现"生产性负债""消费性负债"这类词。

**这笔钱借得划不划算（通用闭环，见 13.5）**：只要一笔债关联了资产，软件自动把两边放在一起算——

- `那项资产"稳稳每月进" − 这笔债当月利息与费用`；
- 结果为正："它替你付了利息，还每月多留 X 元"；为负："它每月从你口袋拿走 X 元，比利息还多"；
- 只取 6.3 标了"每月都有"的进账，分红、"说不准"的租金不参与；本金部分不算"拿走的钱"（见 7.12）；
- T5「应急借的」单独写一句"这是应急，不是乱花"，不按消费问题给建议；
- 所有债按这个结果汇总到 7.9 的「借钱买的东西划不划算」。

> 判断的是现金流的方向，不是给用户的行为打分。

### 7.3 还款方式

等额本息、等额本金、随借随还、先息后本。

> 软件会自动算出"每期该还多少"。用户不懂这些名词没关系，选错了软件会按选的算；软件也会在旁边用一句话解释"等额本息：每期还一样的钱"。

### 7.4 记一笔负债要填什么

| 字段 | 界面上写 | 必填 |
|------|----------|------|
| 欠的什么钱 | 类型（7.2 保留） | 是 |
| 欠谁 / 起个名 | "XX 银行房贷" | 是 |
| 借来干了什么 | 7.2 的用途标签 | 是 |
| 当初借了多少 | 原始本金 | 否，强烈建议填（算进度与真实成本） |
| 现在还欠多少 | 当前剩余本金 | 是 |
| 要不要付利息 / 费用 | 开关 | 是 |
| 合同上写的利率 | 名义利率 | 计息时必填 |
| 实际一年要付多少 | 自动算，含全部费用（见 7.5） | 自动 |
| 三选一的输入方式 | 每期还多少 / 每期费率 / 直接填年化 | 三选一 |
| 利率会不会变 | 固定 / 浮动 + 重定价日 + 加点（见 7.6） | 是 |
| 从哪天借的 / 什么时候到期 / 每月几号还 | 三个日期 | 是 |
| 怎么还 | 等额本息 / 等额本金 / 随借随还 / 先息后本，各带一句白话 | 是 |
| 每期还多少 | 本金 / 利息 / 费用分列，软件按方式自动算，用户可覆盖 | 自动 |
| 已经还了几期 / 一共几期 | 进度 | 否 |
| 从哪张卡扣 | 关联一个流动资金账户，作为扣款来源 | 是 |
| 这笔钱买来的东西 | 关联资产 | 否 |
| 有没有抵押 / 担保 / 共同借款人 | 备注 + 关联"万一要我还的钱" | 否 |
| 提前还要不要另外交钱 | 违约金 / 剩余手续费 | 否 |
| 状态 | 正常 / 逾期 / 已重组 / 已结清 | 自动 |
| 备注、合同照片 | 可选 | 否 |

**部分类型的默认值（自动填，不可改）**：

| 负债类型 | 要不要利息 | 怎么还 | 说明 |
|----------|------------|--------|------|
| 信用卡 | 看怎么还（见 7.7） | 随借随还 | 全额还清才有免息期；只还最低、办分期、逾期各有各的算法 |
| 房贷 | 要 | 默认等额本息，可改等额本金 | 最典型的长期贷 |
| 借的亲友钱 | 不要 | 随借随还 | 可手动开启计息 |
| 电商分期 | 看情况 | 等额本息 | 常说"免息"，但可能收手续费，一律按 7.5 折算真实成本 |

**还款记录字段**：哪天还的、还了多少、其中本金 / 利息 / 费用各多少、从哪张卡、这次是全额 / 最低 / 分期 / 部分 / 提前、还完还剩多少、有没有新产生利息或罚息、备注。

**流向账在债务侧怎么落地**：一笔债不需要用户再填"每月进/每月出"。软件由还款计划自动带出"这个月要还多少"，并把其中的利息与费用汇总成"这笔债每月从口袋拿走多少钱"，与资产的「每月出」一起进入 6.8 的"每月自动出去的钱"；本金部分只是把现金换成少欠一点，不算拿走的钱（见 7.12）。

### 7.5 真实成本：只填"年利率"远远不够

「免息分期」不等于免费：月费率 0.6% 表面年化 7.2%，但因为每期都在还本金、手续费却按初始本金全额收，用实际占用本金折算约 13%~13.8%；10 万元分 12 期的免息分期，实际年化可达 16.22%。只还最低还款额则不再享受免息，从记账日起按日计息，日息万分之五单利折年化约 18.25%，按月复利实际更高，且部分银行采用全额计息。贷款产品应明示按实际占用本金折算的年化利率。

**所以债务的真实成本字段是**：

| 字段 | 界面上写 | 说明 |
|------|----------|------|
| 银行说的利率 | 合同上写的那个数 | 原"年利率"，保留 |
| 实际一年要付多少 | "这笔钱实际一年要付多少" | **自动算，含所有费用**，是排序、比较、推演的唯一依据 |
| 除了利息还交了什么 | 手续费、服务费、保险费、担保费、账户管理费 | 逐项可加，可只填总额 |
| 提前还要不要另外交钱 | 违约金 / 剩余手续费 | 影响 7.10 的决策 |

**用户怎么填（不要求懂任何计算）**，三选一，软件反算：

1. "我知道一共借了多少、每期还多少、还几期" → 填三个数，软件算出实际一年要付多少；
2. "我知道每期手续费多少" → 填每期费率与期数，软件折算（顺带白话提示"看起来是 7.2%，实际约 13.3%"）；
3. "银行直接告诉我年化多少" → 直接填，标"以你账单上写的为准"。

**防错**：各行、各卡规则不同，软件不能冒充银行。设置里放"按我这张卡的规则"（计息方式、日利率、是否按月复利、容时容差），给出常见默认值但标"以你自己的账单为准"；所有利息估算结果一律带**"估算，以账单为准"**。这既守住"不联网"的承诺，也守住"绝对不能出错"。

**扣掉物价上涨，这笔债真正吃掉多少（见 13.1）**：「实际一年要付多少」可以点开一层，用 8.2.2 里用户填的"东西一年贵百分之几"做对照，白话写"如果东西一年贵 2%，这笔 13.3% 的债真正吃掉你约 11.3%"。**这只是一句解释，不改变任何计算**：7.9 的排序、7.10 的"先还哪一笔"、8.2.2 的「利率涨了」一律仍按含全部费用的 13.3% 算。用户没填过物价假设时，这一层不显示，不替用户猜一个数。

### 7.6 利率会不会变

| 字段 | 界面上写 |
|------|----------|
| 利率是固定还是会变 | "一直不变 / 会跟着变" |
| 会变的话跟什么变 | 挂钩 LPR 加多少个点、当前值 |
| 什么时候会重新算 | 重定价日（如每年 1 月 1 日 / 放款日） |
| 有没有优惠期 | "前 X 年便宜一点，之后恢复" |

挂钩 LPR 加点的浮动利率贷款通常每年重定价一次，固定利率在期限内不受影响。所以 8.2.2 里「利率涨了」这个推演情景**只能作用于浮动部分**，固定部分不动；先息后本、随借随还与等额本息的重算方式也各不相同，不能一刀切。

### 7.7 信用卡：从刷卡到还清

建一张信用卡（3.4）时，软件自动建一条对应负债。之后：
- 用信用卡记支出 → 信用卡已用额度 + → 负债剩余本金 +
- 还信用卡 → 负债剩余本金 − → 已用额度 −

用户只管记支出和还款，两边自动同步，绝不会只改了一边。**但"还一笔"不是只有一个数**，还款时用户先选"这次怎么还"（一步，不套弹窗）：

| 选项 | 软件自动做什么 |
|------|----------------|
| 全额还清 | 按账单金额还清，免息，不产生新利息 |
| 只还最低 | 计算循环利息（按该卡计息方式），**把这笔利息自动记成一条新的欠款**，负债不降反升的部分明确显示 |
| 办了分期 | 把这笔账单转成分期负债，按 7.5 折算实际一年成本，生成分期计划 |
| 只还一部分 | 按未还金额与天数估算利息，标"估算" |
| 逾期了 | 罚息 + 违约金单列，不悄悄改本金 |
| 取现 | 不享免息，单独记手续费与利息 |

首页提醒沿用 3.4 的提前 3 天，写成更有用的话："你的 XX 卡还有 3 天要还 8,000 元。全额还清没有利息；只还最低 800 元，下个月大约会多出 235 元利息。"

**信用卡"还能刷的额度"永不进入"现在能花的钱"**（3.4 已定）。

### 7.8 每期还款计划

对分期类负债（房贷、车贷、网贷、分期），软件自动生成一张"还款计划表"：

| 期数 | 哪天还 | 还多少本金 | 还多少利息 | 还多少手续费 | 还完还剩多少没还 | 状态 |
|------|--------|------------|------------|--------------|------------------|------|
| 第1期 | 2026-11-05 | 2000 | 800 | 0 | 198000 | 待还 |
| 第2期 | 2026-12-05 | 2008 | 792 | 0 | 195992 | 待还 |

- 每期状态：待还 / 部分已还 / 已还 / 逾期 / 已重组 / 已结清。
- 用户每还一笔，在计划表里勾"已还"，本金随之减少，下期"还剩多少"自动更新。
- 每期都显示一句白话："这一期里，有 X 元是真给银行的，Y 元只是从左口袋换到右口袋"（利息 vs 本金）。
- 到了还款日，首页提示"你的房贷第 X 期 2800 元明天到期"。
- 利率变更、LPR 重定价、展期、提前还款、借新还旧时，**重算并另存为新版本，旧版本保留可对比**，不得覆盖（与 6.4 价格变动记录同一规则）。
- 逾期产生的罚息、违约金单独成行，不并入本金。
- 还完最后一期后：房贷提示"要不要记一下抵押解除"，信用卡自动恢复循环额度，担保类解除"替别人担的"标记。
- 同一笔债不允许同时存在两个"正在生效"的还款计划版本。

### 7.9 负债统计与债务可持续性

原设计只看余额与当月到期，不足以发现风险。补齐（界面全用白话）：

| 界面上的名字 | 怎么算 | 为什么需要 |
|--------------|--------|------------|
| 一共欠多少 | 所有剩余本金合计 | 原有 |
| 这个月要还多少 | 当月到期应还合计 | 原有 |
| 利息占还款的多少 | 当月利息 ÷ 当月还款 | 原有 |
| 这个月白给银行多少钱 | 月利息与费用合计，及其占收入比例 | 还本金是储蓄、付息才是消耗，这是判断债务质量最核心的一列 |
| 每月要还的钱占每月挣的比例 | 月还款 ÷ 月收入 | 文档已有 30/50 三档；业界与监管常见口径在 36%~60% 区间，超过 50% 违约风险明显上升；设置里可切"宽松 / 标准 / 保守" |
| 还完债还能剩多少 | (月收入 − 每月必须花的钱) ÷ 月还款 | 接近 1 就毫无容错空间，审慎做法常看 1.5 倍以上 |
| 快到期的 | 未来 30/60/90 天到期的负债清单 | 原有 |
| 每个月要还的，那个月拿得出来吗 | 未来 12 个月逐月：这个月要还多少 ÷ 那个月能变成现金的钱（按 6.3「多久能变成现金」排期，见 13.6） | 原设计只拿"今天的能花的钱"去除一整年的债，会漏掉"第 10 个月才到期、到时候却拿不出钱" |
| 哪个月最紧张 | 逐月还款额峰值与所在月份 | 提前知道"明年 3 月要一次拿出 5 万" |
| 借钱买的东西划不划算 | 逐笔：那项资产"稳稳每月进" − 这笔债的月利息与费用（见 13.5） | 区分"借钱买了会生钱的东西"和"借钱填了已经花掉的窟窿" |
| 利率一变你会多还多少 | 浮动利率负债在加息 1 个点下的月供增量 | 与 7.6、8.2.2 打通 |
| 万一要我还的钱 | 或有负债合计（见 7.11） | 默认不进总账，但必须看得见 |
| 万一出事，有人替我付吗 | 7.11 对称清单里"最多能替我付多少"合计（见 13.10） | 与上一行成对出现：一边是可能要还的，一边是有人兜底的 |
| 还有几期还完 | 各笔负债的进度 | 原有 |
| 是不是已经资不抵债 | 净资产为负时显著提示，并附一句"刚工作 / 还在读书时欠着助学贷很正常，别只看这个数"（见 13.9） | 附录 D 已有要求，落到界面 |

**逐月缺口表（替换原来的单一比值）**：软件按未来 12 个月逐月列出「这个月要还多少」「到那个月能变成现金的钱有多少」「差多少」，缺口月标红并给一句人话："明年 3 月要还 5 万，那个月能马上拿出来的只有 2 万，差 3 万。"资产按 6.3 的「多久能变成现金」排到对应月份：随时 / 几天的算进当月，几个月的算进对应月份，动不了的不算；提前变现要扣的钱（13.7）先从里面减掉。

**"每月固定能拿到的钱"口径统一**：用 5.2 用户自己标记的稳定性，不把资产买卖、报销冲减、借入款项算作收入；判断"不上班也能撑住"时，再按 13.2 只取"每月都有"的那一档。

### 7.10 提前还款与"先还哪一笔"

原设计只说"提前还 1 万，能省 X 元利息，要现在还吗？"，这在经济上不完整——还必须回答"这笔钱拿走之后，你还安不安全"。

**提前还款必须同时给出四件事**，一句话结论放在最前面：

1. 能省多少利息与费用（按剩余期数重算，留新版本）；
2. 要不要交违约金 / 剩余手续费，扣完实际净省多少；
3. 还完之后"现在能花的钱"还剩多少、够撑几个月必须花的钱；
4. 一句建议："省 1.2 万利息，但应急金会降到 1.4 个月。建议先留够 3 个月，再拿多余的钱还。"

**多笔债时给"先还哪一笔最划算"**：默认按 7.5 的"实际一年要付多少"从高到低排，白话"先还最贵的那笔，一年能少付 X 元"；同时提供"先还最小的一笔，容易坚持"作为可选。界面给一句解释："提前还掉一笔实际成本 13.3% 的分期，相当于稳稳省下 13.3%，比多数理财都划算。"

> 设计者口径：额外还款的边际收益等于该笔债的实际融资成本，是几乎无风险的回报；但前提是应急金还在。

**再加一句物价提醒（见 13.1）**：若用户在 8.2.2 填过"东西一年贵百分之几"，且这笔债是固定利率，结论后面跟一句"物价涨得比这笔记息快时，慢慢还反而划算；这只是提醒，不用你算"。**不改成建议、不替用户做决定**，四件事的结论顺序与数字都不变。

### 7.11 "万一要我还的钱"

担保、共同借款、还没动用的信用额度、已签合同但还没付的尾款、可能要承担的连带赔偿，都属于"现在不用还，但真出事就得还"。

- 单独一张清单，界面叫"万一要我还的钱"；
- **默认不计入"一共欠多少"，也不进净资产**（避免污染家底账）；
- 每笔填：替谁担的、最多可能要还多少、什么情况下会轮到我还、大概什么时候；
- 健康分析里给一句提示；沙盒推演里可一键加入"万一这笔要我还"的压力情景；
- 真的需要代还时，点"转成我欠的钱"，才正式进入负债模块并生成还款计划。

**对称的另一张清单：万一出事，有人替我付吗（见 13.10）**

上一张记的是"可能要我还的"，这一张记的是"出事时有人兜底的"——收入中断、大病、责任这类尾部风险，家庭最该先看的就是有没有人替自己付。

- 界面叫「万一出事，有人替我付吗」；每笔填：保了什么、最多替我付多少、什么情况不赔、保到哪天；
- **不计入净资产、不算资产、不抵扣负债**，与上一张清单在 7.9 里成对显示；
- 健康分析里给一句提示；沙盒推演里可一键加入"这笔保障用上了"的情景；
- 唯一可编辑入口就在本节，其余位置都是只读展示；
- 软件不评价保障够不够、不推荐任何产品，只把用户填的数摆出来。

### 7.12 债务 ↔ 资产 ↔ 账户 的关联与记账方向

- 一笔债可指向"这笔钱买来的东西"（房贷 → 那套房，车贷 → 那辆车），软件据此给出完整闭环：
  > "这套房现在值 100 万，还欠 70 万，每月租金 0、月供 4,000（其中利息 2,500）、物业 500 —— 它每月从你口袋拿走 3,000 元。"
- 还款必须从关联账户扣，且在账户流水留痕；
- **记账方向必须写死**（修"还了钱净资产却没变"的困惑）：
  - 本金部分：账户 −X、负债 −X → **净资产不变**，只是把现金换成了少欠一点；
  - 利息与费用部分：账户 −Y、生成一条"借钱的成本"→ **净资产减少 Y**，这是真花掉的钱；
  - 还款动作本身**不进"记支出"**，避免重复统计；利息与手续费生成一条类型为"借钱的成本"的支出，默认计入"这个月一共花了多少"，设置里可关（关了要注明"关掉后，这个数会少算一部分真花掉的钱"）；
- 借入一笔钱时：账户 +X、负债 +X → 净资产不变，不记成收入。

### 7.13 防止出错的措施

- 剩余本金只许正数；填 0 时提示"是不是已经还完了？还完可以标记结清"。
- "开了计息"但利率与费用全为 0：提示"这可能是免息分期，要不要按手续费再算一次实际成本？"不擅自改成免息。
- 每期还款额自动算出后，用户改了它，只影响**之后**的期数，已还期数不改，并留痕；软件用一句话确认"你手动改了每期还款额，之后按新金额计算"。
- 还完最后一期：自动提示"这笔钱已全部还清，要标记为结清吗？"结清后不再出现在待还提醒里，但记录保留可查。
- 一笔负债标记为结清后，不允许再记还款；若想恢复，走"取消结清"，必须填原因。
- 逾期罚息、复利、循环利息一律作为**新增欠款**留痕，绝不静默并入本金。
- 信用卡利息、分期折算结果一律标"估算，以账单为准"。
- 借款日、到期日、重定价日的先后关系做兜底校验；跨月账单按交易日归属（沿用附录 C）。
- 还款账户被删：记录保留，提示重新关联，不自动清空。

## 八、分析与推演：我的钱够不够，以后会怎样

### 8.1 财务健康分析

#### 8.1.1 看板上的核心指标

用大白话展示，不用专业词：

| 软件上写的 | 实际算什么 | 怎么样算健康 |
|------------|------------|--------------|
| 你真正拥有的钱 | 全部资产 − 全部负债（一次减完，公式见 10.9） | 越多越好，要为正 |
| 你欠的钱占你身家的比例 | 总负债 ÷ 总资产 | 低于 40% 放心，40~60% 注意，超过 60% 危险 |
| 每月要还的钱占每月挣的比例 | 月还款 ÷ 月收入 | 低于 30% 放心，30~50% 注意，超过 50% 危险 |
| 这个月白给银行多少钱 | 月利息与费用合计 ÷ 月收入 | 越低越好；还本金不是消耗，付息才是 |
| 还完债还能剩多少 | (月收入 − 每月必须花的钱) ÷ 月还款 | 1.5 倍以上放心，接近 1 危险 |
| 万一失业，手上的钱能撑几个月 | 流动资金 ÷ 每月必须花的钱 | 3 个月以上放心，1~3 个月注意，不到 1 个月危险 |
| 每月挣的比花的多多少 | (月收入 − 月支出) ÷ 月收入 | 多 20% 以上放心，正负之间注意，花超了危险 |
| 这个月真省下多少 | 月收入 − 月支出（**只看真进真出的钱**） | 这才是这个月多出来的、实打实留住的钱 |
| 这个月先给自己留了多少 | 当月按 4.6「发工资那天先留一笔」记下的转账合计 | 只读；看"先留再花"这个动作有没有做到（见 13.3） |
| 你的东西在变多还是在变少 | (这个月 − 上个月) ÷ 上个月 | 涨了就向好，但要能点开看是"省下来的"还是"改了个数字"（见 8.1.4） |
| 不上班也能撑住多少 | **稳稳每月进来的钱 ÷ 每月必须花的钱** | 100% 就是"不去上班也够花"；差多少直接显示"每月还差 X 元" |
| 不用上班也有钱进账 | Σ 各项资产"每月进" ÷ 月收入 | 只是顺带看一眼，**不作为终点判断**：分母是收入时会把"挣得多"误当成"自由了" |
| 留够应急金后，还多出来多少 | 现在能花的钱 −（要留几个月 × 每月必须花的钱） | 留够 3~6 个月就够；多太多时提示"一直躺在卡里，没在给你挣钱"（见 13.11） |
| 你每月能挣多少，本身最值钱 | 只读展示"每月固定能拿到的钱"，**不估值、不进总账** | "万一不能上班，这份进账就没了"（见 13.9） |
| 真要全变成现金，要扣多少 | 6.8 的摩擦成本合计 | 标"估算，按你填的手续费和税费" |
| 明年哪个月最紧张 | 7.9 逐月缺口表里最大的那个缺口月与金额 | 提前知道要一次拿出多少、那个月拿不拿得出 |
| 万一要我还的钱 | 担保等或有负债合计 | 默认不算进总账，但必须看得见 |

> 每个数字旁边都有一句"这句啥意思"的解释，点一下就展开。比如"你欠的钱占你身家的比例"旁边点开："这是你欠的钱在你全部财产里占的份量。比如你有 10 万、欠了 3 万，占比就是 30%。占比越高，说明你越靠借钱过日子。"
>
> 所有指标都标明自己属于 2.1 的哪本账；「你真正拥有的钱」旁边固定写"这是把房子、存款、投资都算进去的总账，不是你能马上花的钱"。
>
> **两个口径别弄反**：「不上班也能撑住多少」比的是**要花多少**，不是挣多少——一个月挣 5 万但花 4.8 万的人，被动收入 3,000 一样不自由；一个月花 4,000、被动收入 4,100 的人就已经够了。分子只算 6.3 里标了"每月都有"的进账，分红、偶尔的租金、"说不准"的进账只展示、不参与（见 13.2）。
>
> **净资产为负时别把人吓跑**：提示照给，但后面固定跟一句"如果是刚工作、还在读书，欠着助学贷很正常；你现在最值钱的是以后能挣钱的本事，那个不算在这张表里"（见 13.9）。

#### 8.1.2 综合评分

把上面这些指标合成一个 **0~100 分**，并给出等级：

- 80~100 分：优秀
- 60~79 分：良好
- 40~59 分：一般
- 20~39 分：要注意
- 0~19 分：危险

同时给出**具体建议**，不是空话：
- "你的紧急备用金只够撑 0.8 个月，建议至少存到 3 个月必须花的钱"
- "房贷每月还款占你收入 48%，偏高，建议控制新增负债"
- "你这个月可省的开支花了 3200 元，是最大的一笔，要不要看看是哪些？"
- "你那笔电商分期实际一年要付 13.3%，是所有债里最贵的，先还它一年能少付 X 元"
- "提前还这 1 万能省 1.2 万利息，但应急金会降到 1.4 个月，建议先留够 3 个月"
- "明年 3 月要还 5 万，那个月能拿出来的只有 2 万，差 3 万，要不要提前准备？"
- "留够 6 个月应急金后你还多出 8 万一直放在卡里，这笔钱没在给你挣钱；那笔 13.3% 的分期要不要先还掉？"
- "涨了工资，但结余没涨——挣多的那部分只是过了一遍手，要不要先给自己留一笔？"
- "你家的进账几乎全靠一份工资，房子又占了总账的八成，稳是稳，但都压在一处"
- "不上班也能撑住 45%，每月还差 2,200 元；再添一份每月能进 2,200 元的东西就够了"

#### 8.1.3 趋势图

六条折线，可切换：
- 你真正拥有的钱（近 12 个月，按月末快照，见 10.9）
- 每月挣减花（近 12 个月）
- 欠钱占比（近 12 个月）
- 健康评分（近 12 个月）
- **挣得多了，是不是也花得多了**：收入与支出两条线放一起看（近 12 个月）。收入涨、支出也涨、结余没动时给一句"挣多了但没剩下，钱只是过了一遍手"（见 13.3）
- **不上班也能撑住的进度**（近 12 个月）：看这条线是不是在往 100% 爬

#### 8.1.4 这个月多出来的钱，是怎么来的

「你真正拥有的钱」涨了，不等于这个月攒下钱了。点开任意一个月，把家底账的变动拆成四块，每块一句白话：

| 界面上写 | 算什么 | 用户该看懂什么 |
|----------|--------|----------------|
| 真省下来的 | 当月收入 − 当月支出 | 只有这块是"你留住的钱" |
| 改了个数字 | 手填估值更新、估值口径切换带来的变动 | "这部分只是你改了个数，不是新挣的钱" |
| 卖东西赚的 | 已卖出结算的赚亏合计 | 已经落袋的，算数 |
| 借钱买东西 / 还本金 | 资产与负债一进一出的对冲 | 这块对总数没影响，单列出来免得看着像多了钱 |

一句话总结放在最上面："这个月多出来 8,000 元，其中 3,000 是你真省下来的，5,000 是你把房子估值改高了。"

> 设计者口径：这是把富爸爸那句"重要的不是你挣多少，是你留下多少"落到数字上。四块之和必须等于家底账的当月变动，差额为 0；估值更新、口径切换都要留痕，历史月份的快照不重算（见 10.9、13.12）。

### 8.2 财务沙盒推演

#### 8.2.1 这是什么

用户问"万一……我还能撑住吗？"软件帮他算。比如"万一我失业了，手上的钱能撑几个月""万一利率涨了，我每月多还多少"。

软件拿用户**当前的真实数据**当起点，把假设套进去，推演未来 1~60 个月的变化，最后告诉用户结果。

#### 8.2.2 情景清单（用户能选的"万一"）

| 情景 | 用户要填的 | 软件怎么算 | 最后告诉用户什么 |
|------|------------|------------|------------------|
| 万一失业了 | 预计几个月没收入、每月必须花多少 | 手上流动资金每月扣掉必须花的钱 | "能撑 X 个月，第 X 个月开始没钱" |
| 利率涨了 | 涨几个百分点 | **只对浮动利率负债**按重定价日重算月供，固定利率不动 | "每月多还 X 元，一年多花 X 元" |
| 到了利率重新算的日子 | 选哪笔浮动利率的债 | 按重定价日套用新利率，生成新版本计划 | "下个月起每期从 X 元变成 Y 元" |
| 东西一年比一年贵 | 一年大概贵百分之几（可跳过，默认 0） | 把"每月必须花的钱"逐月放大；收入、房价、估值**不自动跟着涨** | "按现在的物价能撑 5 个月，按东西变贵只能撑 4 个月"（见 13.1） |
| 股票基金跌了 | 跌百分之几 | 按"按买入价"与"按用户填的最新价"两种口径分别给结果，**不凭空生成市值** | "按你填的价，资产少了 X 元；按买入价看，还没卖就不算数" |
| 每月多存点钱 | 每月多存多少、存几个月 | 逐月累加流动资金 | "X 个月后手上多了 X 元" |
| 发工资先留一笔 | 每月先留多少、留几个月 | 先扣下这笔再算能花的钱，逐月累加 | "X 个月后先给自己攒下 X 元，结余没被花掉"（见 13.3） |
| 提前还一笔债 | 选哪笔债、提前还多少 | 重算剩余本金和剩余利息，扣掉违约金，再算应急金还剩几个月 | "净省 X 元利息，但急用钱时只能撑 Y 个月，建议……" |
| 收入涨了 | 涨多少（或涨百分之几）、持续几个月 | 逐月累加收入 | "这 X 个月多挣了 X 元"；顺带看支出有没有跟着涨（见 13.3） |
| 收入降了 | 降多少、持续几个月 | 逐月扣减收入 | "这 X 个月少了 X 元，会不会花超" |
| 突然要花一大笔 | 花多少、哪天花、从哪出 | 从指定账户扣掉 | "花完还剩 X 元，会不会透支" |
| 新欠一笔钱 | 欠多少、利率、还多久、怎么还 | 按 7.5 算实际一年成本，加入负债 | "每月要多还 X 元，欠钱占比变成 X%" |
| 新买一项资产 | 是什么、花多少、预计每年挣多少 | 加入资产，算预期收益，现金从账户扣 | "总资产变成 X，每年多挣 X 元" |
| 把投资换成现金 | 选哪个投资、换多少比例、什么时候换 | 投资市值减少，流动资金增加，**先扣 6.8 的摩擦成本** | "名义上卖 X 元，扣掉你填的手续费和税费，真正到手 Y 元"（见 13.7） |
| 房子租出去了 | 选哪套房、每月租金多少 | 6.6 的净流向从负转正，逐月累加 | "它开始每月给你多留 X 元" |
| 房租收不到了 | 选哪套房、空几个月 | 6.6 的租金按 0 计，持有成本与月供照扣 | "这 X 个月这套房每月从口袋拿走 Y 元" |
| 只还最低还款 | 选哪张卡、这期账单多少 | 按 7.7 估循环利息，逐月滚 | "下个月多出 X 元利息，X 个月才还清" |
| 担保要我代还 | 选 7.11 里哪一笔 | 转成真实负债，加入月供 | "每月要多还 X 元，应急金够不够" |
| 应急金不够 | 想撑几个月 | 对比当前备用金和目标 | "还差 X 元，建议每月存 X 元，X 个月补齐" |
| 固定支出变多 | 多花多少、从几月开始、持续几个月 | 逐月累加支出 | "每月少剩 X 元，结余变不变负" |
| 不用上班也有钱进账 | 每月多多少、持续几个月 | 逐月累加被动收入，同时更新 8.1.1 的终点进度 | "不上班也能撑住从 45% 升到 62%，每月还差 X 元"（见 13.2） |
| 几件事一起发生 | 勾"常见的坏月份"一键组合 | 失业 + 投资跌 + 房租收不到一起套进去 | "最坏那个月手上会少 X 元，第 X 个月开始没钱"（见 13.8） |
| 其他 | 用户自己写一段假设 | 用户手动指定某个月收入/支出的增减 | 按用户给的数推演 |

> 表格里那些"X 个月""X 元"都是软件用用户自己的数据算出来的具体数字。
>
> 「万一失业了」把收入归零时，归零的是 5.2 里标了"每月都有"的**上班挣的钱**；资产里同样标了"每月都有"的进账（如稳定租金）保留，"偶尔有""说不准"的既不保留也不参与（见 13.2、13.9）。这句口径要写在情景说明里，免得用户以为"失业就等于一分钱不进"。

#### 8.2.3 多个情景叠加 + 冲突检测

用户可以一次勾选好几个"万一"，比如"失业 + 收入降了 + 新欠一笔"。软件按顺序一个个套进去算，顺序固定为：先动收入、再动支出、再动利率与债务、最后动资产价格；结果页写一句"按这个顺序算的"。

**冲突检测**（软件发现矛盾时拦下并解释）：
- 同一笔债，既"提前还清"又"新欠一笔" → "这两件事不能同时发生，请去掉一个"
- "收入涨了"和"收入降了"作用在同一个收入来源上 → "不能既涨又降，请去掉一个"
- 选了"失业"，但没去掉"工资收入" → "失业期间一般没有工资，要去掉工资项吗？"
- 同一套房既"自己住"又"租出去了" → "一套房不能同时自住和出租，请选一个"
- 失业了，但"房子租出去了"的租金还在 → "租金收入不受失业影响，要保留吗？"
- 对同一笔固定利率的债勾了"利率涨了" → "这笔利率一直不变，涨利率影响不到它，要不要换成那笔会变的？"
- 勾了"东西一年比一年贵"，又勾了"利率涨了" → 不拦，但结果页注明"这两件事有时会一起发生，这里按你填的两个数分别算"

**一起发生的提醒（不是冲突，是相关）**：用户只勾了"失业"时，软件给一句轻提示："工作没着落的时候，投资常常也在跌、房租也可能收不到，要不要把这几件事一起算？"由用户点一下决定，不擅自加情景（见 13.8）。

#### 8.2.4 推演结果怎么呈现

- **一张总表**：推演前后对比。推演前你真正拥有 X 元、每月结余 Y 元；推演后变成 X' 元、Y' 元。
- **两组数并排**：凡涉及"东西一年比一年贵"，同时给"按现在的物价"和"按东西变贵"两组结果，并写一句"下面这些钱数没变，但能买到的东西变少了"。
- **一条逐月折线**：未来每个月手上的钱怎么变，哪里跌破 0 一目了然。
- **一张逐月缺口表**：每个月要还多少、那个月能拿出来多少、差多少（取 7.9 的算法），缺口月标红。
- **关键节点标注**：比如"第 7 个月开始没钱""第 12 个月结清房贷""第 20 个月物价涨了 10%"。
- **一句人话总结**："按这个假设，你手上 8000 元能撑 4 个月，第 5 个月开始透支。建议提前准备至少 16000 元应急金。"

#### 8.2.5 保存推演

- 每次推演自动存下来：起个名字、当时填了什么假设（含"东西一年贵百分之几"）、得出什么结果、什么时候算的。
- 历史推演列表：用户能回看"我三个月前算过一次失业，当时能撑 3 个月，现在能撑 5 个月了"。
- 对比功能：选两次推演并排看，数字差多少；若两次填的物价假设不同，标一句"这两次物价假设不一样，别直接比"。

### 8.3 防止出错的措施

- 推演不改变真实数据。它是"沙盘推演"，所有操作在副本上进行，用户真实的账户、收支、资产、负债一字不动。
- 推演中出现透支（手上钱变负），软件标红但不报错，因为这正是用户想看的"最坏情况"。
- 推演月数上限 60 个月（5 年），超出提示"时间太长结果会不准，建议缩短"。
- 推演里用到的"现在"数据，如果用户在推演后又改了真实数据，历史推演记录保留当时的快照，不会跟着变（保证回看结果一致）。
- 推演用到的市值一律来自"按买入价"或"用户填的最新价"，并标"这是你 X 天前填的"；软件不联网，不生成任何行情数。
- **"东西一年比一年贵"是用户自己填的假设，不是查来的数**：默认 0、可跳过，结果页固定标"按你填的每年贵 X% 算的"；软件不联网取物价数据，也不预测物价（见 13.1）。
- 名义金额与实际购买力不得混成一个数：所有真实账本、账户余额、历史快照都是**名义金额**；"钱不经花"只在推演副本里体现，回写不到账本（见 3.8、13.1）。

## 十、通用规则（所有模块都要遵守）

这些是不属于任何一个模块的硬性约定，但每一处功能都要照着做。

### 10.1 数据存在哪

- 所有记账数据（账户、支出、收入、资产、负债、推演记录）**全部存在本地设备**，不上传任何远程服务器。
- 知识文章是例外，后续可考虑远程获取。

### 10.2 每条记录都有的公共字段

不管记什么，下面这些软件自动管，用户不用填：
- 创建时间（什么时候建的）
- 修改时间（最后一次改是什么时候）
- 删除标记（删了不是真删，进回收站）

### 10.3 每个账户都要有流水

每张卡、每个账户，都要有一本"流水账"：什么时候进了一笔、什么时候出了一笔、进出后余额是多少。这是用户核对"软件记的跟实际对不对"的唯一依据，必须随时能翻出来看。资产买卖的现金收付、还款、循环利息产生的现金变动，同样进这本流水，但按各自的方向标注，不冒充日常收支。

### 10.4 数字怎么显示

- 所有金额走统一的格式化：加千分位、固定小数位、带货币符号。
- 界面上禁止出现裸数字拼接。
- 大额数字提供"万元"切换，比如"12,5000 元"可显示为"12.5 万"。

### 10.5 分类怎么管

- 支出和收入的分类都只有一层，不分级。
- 资产大类、负债类型同样只选一次，不进二级菜单；选中后只展开这一类专属的几项。
- 用户可以自己加、改名字、删掉不用的。
- 系统预设的分类不能删，但可以不显示（隐藏）。
- 用户可以对分类打"必须花的/可省的""每月都有的/偶尔才有的"标记，不打就不参与判断。

### 10.6 金额只填正数

支出金额、收入金额、余额、价格、数量、股数、份额、额度，统统只接受正数。要表示"减少"，用负数？不行，一律用"类型"区分（比如"支出"和"收入"是两个动作，而不是"正负金额"）。这样用户不会搞混。价格、净值为 0 或空一律拦下，不允许把"不知道"记成 0；确实没有估值时显示"—"，不显示 0。

### 10.7 所有操作可逆

- 修改：随时改，每次修改更新"修改时间"。
- 删除：进回收站，30 天内可恢复，过期自动清理。
- 清空：批量操作时二次确认，且可整体恢复。
- 余额调整：必须填原因，留痕可查。

### 10.8 即时保存

用户每记一笔，软件**立刻**存盘。不允许"点了保存才存"这种延迟——万一保存前闪退，账就白记了。技术上保证记一笔就落地一笔。

### 10.9 准确性铁律

- **账户余额**：`期末余额 = 期初余额 + 收入 − 支出 + 转账 ± 资产买卖的现金收付 + 调整`。任一时刻可审计。
- **家底账**：`真正属于你的钱 = 账户余额合计 + 非账户形态资产估值（投资持仓、房产、车、贵重物品、生意股份、借出款） − 负债合计（含信用卡、亲友借款、已转实的代还）`。现金与受限资金只以账户为准，资产页的 A1/A2 是只读镜像，**不重复加**；借出款、信用卡欠款、亲友借款各只在一处计一次，不再按来源二次加减。
- **恒等校验**：任一笔交易后，上面两个式子必须同时成立，差额为 0。买基金 2 万：账户 −2 万、投资持仓 +2 万，净资产不变，"这个月花了多少"也不变；还房贷本金 1,500：账户 −1,500、负债 −1,500，净资产不变；只有利息部分才让净资产减少。
- **所有自动算的数字**（可用额度、市值、盈亏、每期还款、利息、实际一年要付多少）都必须展示"怎么算出来的"，用户点一下能看到算式。
- **软件绝不在用户背后悄悄改任何数字**，任何自动变动（含循环利息、估值口径切换、还款计划重算）都要在流水里留痕。
- **两本账不得互相冒充**：家底账是某一时点的存量，流向账是一段时间的进出；同一套自住房在两处都显示，但不进"我欠的钱"。
- **估算必须标来源**：软件不联网，手填的价标"你 X 天前填的"，按卡规则算的利息标"估算，以账单为准"，推演结果标"按这个假设"，绝不假装是查来的准数。
- **月末快照锁定历史**：家底账按每月末存一次数（资产、负债、各账户余额、当时的估值口径与估值日期一起存）。之后用户改了房价、改了股价、切了估值口径，**只改当月及以后，历史月份一律不重算**；8.1.3 的趋势与 8.1.4 的归因都读这份快照。补记上个月的账时，只改流水归属，不改写已存的月末总数，差异在归因里单列"补记"（见 13.12）。
- **账本永远是名义金额**：所有余额、估值、欠款、历史快照都是当时填下的钱数，软件不因物价自动调大调小；"钱越来越不经花"只作为 8.2 推演里的可选假设，不回写账本（见 13.1）。
- **"稳稳每月进来的钱"有唯一口径**：只取 6.3 标记"每月都有"、且 5.2 标记"每月都有"的进账；分红、偶尔的租金、"说不准"的进账只展示、不进"不上班也能撑住"、不进压力测试的收入侧（见 13.2）。
- **一个功能只有一个操作入口**：新增的清单（万一要我还的钱、万一出事有人替我付、先给自己留一笔、逐月缺口表、摩擦成本）都只在各自章节有一个可编辑入口，其余地方一律是只读展示或跳转；不违反设计原则第一条。

## 十三、经济学家视角的补充约定（本轮新增）

### 13.0 这一章怎么读

前面十二章解决的是"把账记对"。这一章解决的是"记对之后，能不能看出钱在往哪流、以后撑不撑得住"。

**覆盖关系**：本章条款是对 2~10 章的补充约定；正文已按本章改好的地方（3.6、3.8、6.3、6.8、7.9、8.1、8.2、8.3、10.9、第十二章）以正文为准，本章给算法细则、界面文案与边界；若将来发现某处正文与本章冲突，以本章口径为准并同步修正文。

**两条红线**（沿用最高准则）：
- 界面一个专业词都不露，右列文案就是用户能看到的全部；
- 软件不联网、不取行情、不取物价、不替银行计息，凡属"用户填的"或"按规则估的"都标来源。

**不做什么**（防止范围膨胀，见 13.13）：不做税务筹划、不给投资建议、不推荐产品、不预测物价与利率、不给人身或挣钱能力估价、不自动调账、不替用户做决定。

### 13.1 钱会越来越不经花（购买力与实际成本）

**问题**：文档此前 60 个月推演、房产估值、应急金、固定收入全用**名义金额**。同样 8,000 元五年后能买的东西更少，长期结论会系统性乐观；而"提前还贷划不划算""这笔债贵不贵"只看名义利率也会判偏。

**依据**：实际利率 ≈ 名义利率 − 物价上涨率（费雪效应）；衡量的是**购买力**而不是账户里数字变多多少。通胀对固定收入人群不利，固定利率债务的实际负担会随物价上涨而变轻。[见附四]

**落地**：

| 位置 | 加什么 | 界面上写 |
|------|--------|----------|
| 8.2.2 | 新情景「东西一年比一年贵」 | 用户填"一年大概贵百分之几"，默认 0、可跳过 |
| 8.2.4 | 结果同时给两组数 | "按现在的物价…／按东西变贵…"；"下面这些钱数没变，但能买到的东西变少了" |
| 7.5 | 「实际一年要付多少」可展开一层 | "如果东西一年贵 2%，这笔 13.3% 的债真正吃掉你约 11.3%" |
| 7.10 | 提前还款结论加一行 | "物价涨得比这笔记息快时，慢慢还反而划算；这只是提醒，不用你算" |
| 3.8 / 10.9 | 口径声明 | 账本永远是名义金额，软件不自动调价 |

**边界**：不取真实物价数据、不预测、不默认开启；收入、房价、估值**不自动跟着涨**（否则等于软件替用户编了一串数）。只把"每月必须花的钱"逐月放大。

### 13.2 终点指标：不上班也能撑住

**问题**：原 8.1.1「不用上班也有钱进账的比例 = 被动收入 ÷ 总收入」口径错了。富爸爸的财务自由判据是**被动收入覆盖每月支出**，不是占收入多少；一个人挣得多、花得也多，这个比例可以很好看却依然一停工资就断粮。另外租金会空置、分红不保证，把这些和工资一样算进"稳稳的进账"会高估安全度。

**依据**：财务自由 = 资产带来的现金流 ≥ 每月开支；"财富是用时间衡量的"——停掉工资能撑多久，被动收入永久覆盖支出时这个数趋于无限。[见附四]

**落地**（8.1.1、3.6、6.3、6.8 已改）：

- 主指标：`不上班也能撑住多少 = 稳稳每月进来的钱 ÷ 每月必须花的钱`，配一条进度条，差多少直接显示"每月还差 X 元"；
- 短期 companion：`万一失业，手上的钱能撑几个月`（原有）保留——一个看"能撑多久"，一个看"能不能一直撑"，两条都要；
- 每笔「每月进」加一个标记「每月都有 / 偶尔有 / 说不准」（6.3），**只有"每月都有"进主指标与压力测试的收入侧**；"说不准"的只展示，不参与判断；
- 原「占收入比例」降级为次要展示，旁边注明"这个数会跟着工资涨，别拿它当终点"；
- 8.2.2「不用上班也有钱进账」结果列改成主指标进度，不再报占比。

### 13.3 先付给自己，以及"挣得多了也花得多了"

**问题**：文档只做事后统计（月底看结余），没有富爸爸最看重的**动作顺序**：先买资产、再用剩下的付账单。也没有识别"涨薪后生活水平同步膨胀、结余原地踏步"的老鼠赛跑。

**依据**：先付给自己（Pay Yourself First）——收入到手先划一笔买资产，剩下再生活；老鼠赛跑指收入提高被支出提高吃掉，人更依赖工资。[见附四]

**落地**：

- 4.6 / 3.7：新增「发工资那天先留一笔」。用户在设置里填"每月先留多少"和"留到哪张卡"；工资到账时首页提示"先把 X 元留起来，剩下的再花"，一键记一笔转账（复用 3.7 已有转账，**不新增账户类型、不新增表字段、软件不碰钱**）；
- 8.1.1 新增「这个月先给自己留了多少」的只读展示（可与"真省下多少"并列）；
- 8.1.3 新增一条可切换趋势「挣得多了，是不是也花得多了」：收入线与支出线放一起，收入涨、支出也涨、结余没动时给一句"挣多了但没剩下，钱只是过了一遍手"；
- 8.1.2 新增对应建议；8.2.2 新增情景「发工资先留一笔」。

**边界**：不自动转账、不代扣、不替用户决定留多少；不做行为打分。

### 13.4 这个月真省下多少（家底账变动归因）

**问题**：「你真正拥有的钱」涨了，可能只是用户把房子估值改高了、或切了估值口径，不是真攒下钱。原趋势图只给一条线，用户会把"账面变多"当成"我变有钱了"。

**依据**：富爸爸强调"重要的不是你挣多少，是你留下多少"；经济学上要区分**储蓄流量**与**重估（revaluation）带来的存量变动**，两者性质完全不同。

**落地**：新增 8.1.4「这个月多出来的钱，是怎么来的」，把当月变动拆成四块（真省下来的 / 改了个数字 / 卖东西赚的 / 借钱买东西与还本金的对冲），四块之和必须等于当月变动、差额为 0；配一句人话总结。8.1.3 趋势图按月末快照读，估值更新留痕、历史月份不重算（13.12）。

### 13.5 借钱买的东西划不划算（好债 / 坏债闭环）

**问题**：7.2 已有用途标签 T1~T7，7.12 给了房贷的闭环，但没有**通用规则**把"借钱买来的东西每月给你多少钱"和"这笔债每月白给银行多少钱"自动对照。这正是富爸爸最核心的判断：借钱买资产 vs 借钱填窟窿。

**落地**（7.2、7.9）：

- 对每一笔关联了资产的债，软件自动算：`那项资产"稳稳每月进" − 这笔债的当月利息与费用`；
- 正数："它替你付了利息，还每月多留 X 元"；负数："它每月从你口袋拿走 X 元，比利息还多"；
- 7.9 新增汇总行「借钱买的东西划不划算」，把用途标签 T3 与 T4 分两组列出各欠多少、各月付息多少；
- **不因为标签是 T4 就骂用户**：T5「应急借的」单独说明"这是应急，不是乱花"，避免把风险信号误判成消费问题。

> 设计者口径：判断的是**现金流的方向**，不是道德评价；本金部分不计入"拿走的钱"（见 7.12）。

### 13.6 逐月缺口表（别拿今天的钱去除明年的债）

**问题**：原 7.9「未来一年要还的一大笔 ÷ 现在能花的钱」是期限错配——用**今天**的流动资金去除**未来 12 个月**的债。第 10 个月到期的 5 万，可能到第 10 个月根本拿不出现金，而房子要几个月才能卖。

**依据**：资产与负债要做期限匹配（maturity matching）；家庭压力测试看的是逐月现金流缺口，不是单一时点的覆盖率。[见附四]

**落地**（7.9、8.2.4 已改）：按 6.3「多久能变成现金」把资产排到能到手的月份（随时/几天算当月，几个月算对应月份，动不了不算），先扣 13.7 的变现摩擦，再逐月比对当月应还；缺口月标红并给一句人话。8.2.4 的推演结果复用同一张表。

### 13.7 真要变成现金，一共要扣多少（摩擦成本）

**问题**：房产交易税费、基金赎回费、提前取定期扣钱散落在 6.3 / 6.6 / 6.5 各处，没有一张总表。用户以为"我值 100 万"，真急用钱时到手可能只有 92 万。

**落地**（6.8、8.2.2 已改）：汇总所有资产的「提前拿会不会扣钱」「卖一次大概要交多少」与投资赎回费，给出「真要全变成现金，一共要扣多少」；固定标"估算，按你填的手续费和税费"；8.2.2「把投资换成现金」的结果改成"名义上卖 X 元，真正到手 Y 元"。5.3 的「要不要报税」只做汇总展示，**不做税务筹划、不算税额**。

### 13.8 别把鸡蛋放一处，以及坏事先后来还是一块儿来

**问题**：只有"钱主要压在哪"一个饼图，没看**进账**是不是也只有一处；8.2.3 只查逻辑冲突，不查"这些坏事常常同时发生"。

**落地**：

- 6.8 新增「钱和进账是不是都压在一处」：一套房占总资产、一份工资占总进账过高时给白话提示，不给投资建议；
- 8.2.3 新增「一起发生的提醒」：只勾"失业"时轻提示"工作没着落的时候，投资常常也在跌、房租也可能收不到，要不要一起算？"，由用户点一下决定；
- 8.2.2 新增「几件事一起发生」一键组合与「房租收不到了」情景；
- 不擅自叠加、不擅自改用户填的假设。

### 13.9 你每月能挣多少，本身就是最值钱的东西

**问题**：文档只算已积累的钱。对刚工作、还在读书、背着助学贷的人，净资产为负是生命周期里的常态；此时弹一句"资不抵债，危险"既不准也伤人。同时"失业"情景把收入直接归零，却没说清归零的到底是**什么**。

**依据**：生命周期假说与人力资本——年轻家庭借钱投资于未来挣钱能力，净资产暂时为负很常见；人力资本是家庭最重要却难以精确定价的资产，因此通常**不写进资产负债表**。[见附四]

**落地**（8.1.1、7.9 已改）：

- 只读卡片「你每月能挣多少，本身最值钱」，展示"每月固定能拿到的钱"，旁边写"万一不能上班，这份进账就没了"；
- **绝对不估值、不进总账、不给它编一个金额**（否则违反"绝对不能出错"）；
- 净资产为负的提示后面固定跟一句温和说明；
- 8.2.2「万一失业了」把"收入归零"的对象写明是 5.2 里"每月都有"的那一档，被动收入中"每月都有"的部分保留。

### 13.10 万一出事，有人替我付吗（与 7.11 对称）

**问题**：有「万一要我还的钱」，没有它的镜像。家庭最大的尾部风险是收入中断、大病、责任；保险在支出类型里只是一条"保险"，没地方看"真出事谁兜底、最多兜多少"。

**落地**（7.11 内新增对称清单，7.9 已加指标行）：

- 界面叫「万一出事，有人替我付吗」：保了什么、最多替我付多少、什么情况不赔、保到哪天；
- **不计入净资产、不算资产、不抵扣负债**；
- 与健康分析里「万一要我还的钱」成对出现；推演里可一键加入"这笔保障用上了"的情景；
- 唯一可编辑入口在 7.11，其余只读。

### 13.11 应急金留够就行，多太多也不划算

**问题**：只有下限（3 个月），没有上限提示。现金长期闲置既被物价侵蚀，又错过"先还掉最贵的债"这种几乎无风险的回报。

**依据**：应急金常按 3~6 个月**必需支出**准备；超出实际需要的现金存在机会成本（cash drag）与购买力侵蚀。[见附四]

**落地**（3.6、8.1.1、8.1.2 已改）：

- 用户设"想留几个月"（默认 3，可改 6 或更多）；3.6 加只读行「留够应急金后，还多出来多少」；
- 超过 12 个月必需支出时提示"一直躺在卡里，没在给你挣钱"，并与 7.10「先还最贵的那笔」联动给一句建议；
- **不自动把钱转去还债、不推荐任何产品**；收入不稳定、单一收入来源、有抚养负担时把提示阈值放宽（用户可在设置里调）。

### 13.12 月末快照与历史锁定

**问题**：8.1.3 的 12 个月趋势没说清数据怎么存。若用"当前公式回溯"重算历史，用户今天改了房价，会连去年的曲线一起改掉，违反"历史结算不覆盖"与"回看结果一致"。

**落地**（3.6、8.1.3、10.9 已改）：每月末存一份快照（各账户余额、资产估值、负债剩余本金、当时用的估值口径与估值日期、当时的分类标记）；之后改价、切口径、改分类标记只影响当月及以后；补记旧账不改写已存月末总数，在 8.1.4 归因里单列"补记"。历史推演同理（8.2.5、8.3）。

### 13.13 边界、唯一入口与排期

- **不做**：税务筹划与税额计算、投资建议与产品推荐、物价与利率预测、人身/人力资本估价、自动调账、自动转账、代扣代付、行为打分、道德评价。
- **唯一入口**：新增五处可编辑清单各自只有一个入口（7.11 两张清单、4.6「先留一笔」、6.3「稳不稳」标记、8.2.2 情景），其余位置全是只读展示或跳转，不违反"一个功能只在一个地方出现"。
- **账户模块影响**：仅 3.6 两行只读数字 + 「变化趋势」一行文案、3.7 一条复用转账的说明、3.8 一句名义金额注释，**无新增账户字段、无新增账户类型、无流程改动**。
- **排期**：见第十二章 2c；P0 是 13.2、13.4、13.12（口径与正确性），P1 是 13.1、13.3、13.5、13.6、13.7、13.11，P2 是 13.8、13.9、13.10。

## 附：财务专家视角的全局校验清单

这一节是给设计者自查用的，确保这套设计在数学和逻辑上站得住脚。**用户不会看到这一节**。

**A. 恒等式与守恒**
- 账户体系满足：期末余额 = 期初余额 + Σ(流入) − Σ(流出) ± Σ(资产买卖现金收付) + Σ(调整)。任一时刻可审计。
- 净资产 = 账户余额合计 + 非账户形态资产估值 − 负债合计。三个量任一变动，联动方向必须正确；现金与受限资金只以账户为准，A1/A2 镜像只读，绝不重复计入。
- 借出款、信用卡欠款、亲友借款各只计一次；3.6 的分列项不参与净资产的二次加减。
- 买资产是"现金 ⇄ 东西"的转换，净资产不变、当月收支不变；卖出结算的赚亏才改变净资产。
- 还本金是"现金 ⇄ 少欠一点"，净资产不变；付息与费用才让净资产减少。
- 信用卡是"负债"在账户体系里的镜像，两边状态必须原子同步，不允许只改一边。
- 循环依赖防护：账户联动更新不得形成环，需明确更新主从关系（账户为主、资产镜像为从）。

**B. 口径一致性**
- "总资产"和"真正拥有的钱"必须同时给出且关系明确，避免用户把"能看到的总数"误当成"能花的钱"。
- 家底账（存量）与流向账（每月进/出）分开算、分开显示，不得互相冒充；自住房、车在流向账里是"拿钱的东西"，但不进负债模块。
- 公积金、社保这类受限资金：计入总资产，但不计入流动资金，在沙盒推演中默认不可动用（除非用户显式指定用途）。
- 借出/借入：同属"净资产"但方向相反，需在统计中分列，避免一进一出差额抵消导致用户误判"我没借钱"。
- A1/A2 只读镜像；镜像断开时保留旧值但不参与总账，不允许静默沿用。
- 或有负债（担保等）默认不进净资产，只有"转成我欠的钱"才进。
- 报销到账是冲减，不是收入；资产买卖回款、借入款项、转账都不算收入。
- "每月出"只记资产自己的持有成本，借款月供与利息统一由负债模块算，不重复扣。

**C. 时间维度**
- 每笔交易带精确时间戳，所有"月/周"统计以交易时间归属为准，不以录入时间为准（用户可能月底补记月初的账）。
- 跨月账单（如信用卡账单日出在月末、还款日在次月）需明确归属期，避免"这个月花超了"其实是上个月的账。
- 估值日期必须与数字同屏显示；超过 90 天未更新的数在总账上标提示。
- 还款计划重算另存新版本，旧版本保留可对比；历史结算不因计价方式切换而重算覆盖。

**D. 边界与异常**
- 所有金额为非负小数，用"方向"区分流入流出，不用符号；价格/净值/数量为 0 或空一律拦下。
- 除零、空值、负数、超精度、超大数均有兜底；净值为负允许存在（确实资不抵债），但要显著提示。
- 卖出数量不得超过持仓；关联账户被删时保留记录、提示重关联，不自动改历史金额。

**E. 数据安全与可追溯**
- 单写点原则：余额只由流水驱动，禁止直接覆写；资产镜像、关联账户都不构成第二个写入点。
- 所有变更留痕（谁、什么时候、改了什么、为什么），回收站提供完整恢复。
- 持久化即时落盘，事务边界清晰，崩溃恢复后数据不丢、不重复。

**F. 推演的可信度**
- 推演基于真实数据快照，不改真实数据，不与真实数据混淆。
- 线性外推假设必须显性声明（如"假设支出不变""假设利率不变"），避免用户把推演当预言。
- 多情景叠加时执行顺序影响结果，需固定顺序（收入 → 支出 → 利率与债务 → 资产价格）或明确告知用户。
- "利率涨了"只作用于浮动利率部分并带重定价日；固定利率不动。
- 推演不得凭空生成市值：只用"按买入价"或"用户填的最新价"，并标明数据日期。
- 提前还款结论必须同时给出利息节省、违约金、应急金剩余月数，不能只报省了多少。
- "东西一年比一年贵"是用户填的假设、默认 0、可跳过；结果必须同时给名义与实际两组数，不得把二者混成一个数字。
- 相关情景（失业 + 投资跌 + 房租收不到）只能由用户主动一键叠加，软件不擅自加。

**G. 本轮补充约定的校验（对应第十三章）**
- 财务自由度的分母是**每月必须花的钱**，不是月收入；分子只取"每月都有"的进账。
- "稳稳每月进来的钱"全软件只有一个口径（5.2 与 6.3 两处标记都满足），任何统计、指标、推演都引用同一份结果。
- 8.1.4 归因四块之和 = 家底账当月变动，差额为 0；估值更新、口径切换、补记旧账都留痕。
- 月末快照一经存入不可回溯改写；改价、切口径、改分类标记只影响当月及以后。
- 名义金额与实际购买力分离：账本、账户余额、历史快照全是名义数；物价上涨只在推演副本里生效。
- 逐月缺口必须逐月配对（那个月的应还 vs 那个月能到手的钱），不得用"今天的能花的钱"去除一整年的债；能到手的钱先扣变现摩擦。
- 摩擦成本是估算，必须标"按你填的手续费和税费"；5.3 的报税标记只汇总、不算税额。
- 人力资本只读展示，**不估值、不进总账、不编造金额**；净资产为负的提示必须带生命周期说明。
- "万一出事有人替我付"与"万一要我还的钱"都不进净资产；只有"转成我欠的钱"才进。
- 应急金上限只给提示与建议，不自动转账、不自动还债、不推荐产品。
- 新增清单各自只有一个可编辑入口，其余只读；不违反"一个功能只在一个地方出现"。
- 全程不出现专业词；所有估算标来源与时间；不预测物价、利率、行情。

## 附三：端到端验收算例（给设计者与测试自查，用户不会看到）

> 以下数字全部为示例，只用于校验等式；界面上不会出现这些算式。

**起点**：工资卡 50,000，无负债 → 真正属于你的钱 50,000。

**① 买基金 20,000**（单价 2.000、10,000 份、无费用）
- 工资卡 30,000；基金持仓成本 20,000；"这个月花了多少"**不增加**。
- 净资产 = 30,000 + 20,000 = 50,000 ✓
- 界面："按买入时算，没算涨跌""还没卖，先不算赚没赚"。

**② 分红 300 到账**
- 工资卡 30,300；收入 +300；基金"每月给你多少钱"累计 300。
- 净资产 = 30,300 + 20,000 = 50,300 ✓

**③ 卖出一半**（5,000 份、单价 2.500、无费用）
- 到手 12,500 → 工资卡 42,800；本次成本 10,000；**这次赚 2,500**；剩余持仓成本 10,000。
- 净资产 = 42,800 + 10,000 = 52,800 = 50,000 + 300 + 2,500 ✓
- "这个月一共挣多少"**不增加** 12,500。

**④ 另有一套自住房**：估值 1,000,000，房贷 700,000，月供 4,000（本金 1,500 + 利息 2,500），物业等持有成本 500/月，自住无租金。
- 家底账：房子 +1,000,000、房贷 −700,000 → 这套房给净资产贡献 +300,000。
- 流向账：每月从口袋拿走 = 物业 500 + 房贷利息 2,500 = **3,000**（月供本金 1,500 不算费用，不重复计）。
- 当月还款后：账户 −4,000、负债 −1,500 → 净资产只减少 2,500 ✓
- 若改为出租、月租 4,500：净流向 = 4,500 − 500 − 2,500 = **+1,500**，界面改口"它开始给你钱了"。

**⑤ 信用卡**：账单 8,000，只还最低 800。按该卡规则估算下期循环利息约 235，软件把它记成一条新欠款并提示"实际欠的钱变成了约 7,435，不是 7,200"；"还能刷的额度"始终不出现在"现在能花的钱"里。

**⑥ 本轮新增口径的联算**：每月必须花的钱 4,000；稳稳每月进来的钱 = 房租 1,200（标"每月都有"）+ 分红折算 200（标"说不准"，不计入）= 1,200。
- 不上班也能撑住 = 1,200 ÷ 4,000 = **30%**，界面"每月还差 2,800 元" ✓（不是 1,400 ÷ 月收入）
- 某月工资 8,000、支出 6,000，同时用户把房子估值从 100 万改到 105 万：家底账当月 +7,000，8.1.4 归因 = 真省下 2,000 + 改了个数字 5,000 ✓，"这个月真省下多少"只显示 2,000
- 一笔分期实际一年要付 13.3%，用户填"东西一年贵 2%"：可展开提示"真正吃掉你约 11.3%"，但 7.5 的排序、7.10 的"先还哪一笔"仍按 **13.3%** 算，不按 11.3% 改 ✓
- 推演「东西一年贵 2%」只把"每月必须花的钱"逐月放大，账户余额、房价、工资**一分不动**；结果同时给"按现在的物价能撑 5 个月 / 按东西变贵 4 个月" ✓
- 用户 3 个月后把房价又改高：1~3 月的月末快照与 8.1.3 曲线**不变**，8.1.4 的历史归因也不重算 ✓

## 附四：口径依据（设计者自查，用户不会看到这一节）

- 富爸爸对资产/负债的"钱往哪流"定义，以及自住房、车在不同用途下的归类：Rich Dad 官网、中央财经大学财经新闻研究所、经济参考报、香港财经时报的相关介绍。
- 财务自由的判据（资产现金流 ≥ 每月开支）、"财富用时间衡量"、先付给自己与现金流象限：Rich Dad 官网《How to be Financially Free》《Rich vs. Wealthy: The Difference...》、央视网对清崎"被动收入足以支付总支出即财务自由"的介绍、相关书评对 Pay Yourself First 与老鼠赛跑的整理。
- 家庭资产负债表的标准分类（金融资产 / 非金融资产 / 负债 / 净值）：ESA 2010 口径下的比利时国家银行说明、英国议会援引 ONS 家庭资产负债表、中国社会科学网《中国居民资产负债表估计：1978—2019》、家庭资产负债表词条；人力资本作为扩展资产负债表项目见 IMF 相关口径资料。
- 生命周期与人力资本：纽约联储 Liberty Street Economics《Which Households Have Negative Wealth?》（年轻、高学历家庭净资产为负符合生命周期模型）、生命周期假说关于人力资本与金融资本平衡的通常表述。
- 信用卡最低还款、循环利息与分期手续费的真实成本：央视网、中国经济网、新华报业网相关报道；中国人民银行公告〔2021〕第 3 号关于明示年化利率、按实际占用本金折算的要求。
- 名义利率、实际利率与物价：费雪效应（实际利率 ≈ 名义利率 − 通货膨胀率）——广州市地方金融管理局、央广网《"提前还房贷"是好的选择吗》、中国社会科学院相关研究对费雪方程式与债务负担的说明。
- 偿债收入比与风险阈值：负债收入比、月所有债务支出与收入比的通行口径，FDIC 关于 DTI 超过 50% 的风险提示。
- 应急金与现金的机会成本：以 3~6 个月**必需支出**为常见起点、超额现金存在 cash drag 与购买力侵蚀的家庭流动性资料；期限匹配（按需要用钱的日期安排可变现资产）的一般原则。
- 浮动利率与 LPR 重定价机制：贷款定价相关公开资料。

> 口径声明：以上仅用于校准设计逻辑；软件本身不联网、不取实时行情、不取物价数据、不代替银行计息，所有由用户手填或按账单规则估算的数字都在界面上标明来源与时间。
